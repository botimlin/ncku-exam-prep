# 壓力測試結果（2026-11-11～12，RTX 4090 24GB）

## 測試條件
- 伺服器：Ollama v0.40.16，模型都是 Ollama 預設 4-bit 量化（Q4_K_M；gpt-oss 是 MXFP4），context 8192。
- 模型：gpt-oss:20b、qwen3:8b、gemma3:12b、qwen2.5:14b、phi4:14b、mistral-nemo:12b、qwen2.5:7b、llama3.1:8b、qwen2.5:3b、llama3.2:3b。

- 每個案例跑 temperature 0 和 0.7 各 2 次（推理模型 gpt-oss、qwen3 各 1 次，max_tokens 6000）。
- 評分：自動檢查格式（固定欄位、長度、patch 格式）、grounding（引用要在資料裡、資料沒有要說「資料中沒有」）、正確性（選對類別、指出正確的 bug）。

## 怎麼重現
```bash
python3 run.py --validate-cases
python3 run.py --base-url http://127.0.0.1:11434/v1 --model gemma3:12b --temperature 0,0.7 --repeat 2 --out out/x
python3 analyze.py out/x --rescore
```
原始回答在 `results/`（不放進 git）。

## 還是偏弱、用的時候要特別核對的卡
- **範本 2/7（題目規格 → 範本對照）**：第 9 輪 4 個模型只有 25%。模型常把「要改」判成「範本沒有」，證據也常是自己寫的句子。用法：當作「提醒我看哪些地方」，每一列自己打開範本確認。
- **除錯 3/6（看不懂的錯誤訊息）**：約 50%。常見原因要靠知識（例如 pyserial 套件名），小模型會猜。
- **除錯 1/6、優化 2/6**：需要硬體知識或自己想方案的題目，先貼對應的參考卡（例如 `pico-dma.md` 2/8）再問。
- **3B 等級模型**：格式跟得上，判斷常錯；任何結論都要對一次證據。

# 第二部分：過夜測試（2026-11-12）

## A. context 長度（4k vs 8k，同一批 70 個案例）
| 模型 | 8k | 4k | 4k 被截斷 |
|---|---|---|---|
| gemma3:12b | 69% | 76% | 0 |
| qwen2.5:14b | 75% | 76% | 0 |
| qwen3:8b | 69% | 65% | 6 |
| gpt-oss:20b | 84% | 76% | 8 |
- **單張卡在 4k 完全放得下**（最長約 2200 token）。一般模型不受影響；推理模型會因為「想太多」被截斷而掉分。
- 推理模型在訊息最後加 `Reasoning: low`（gpt-oss）：推理量少約 1/4、快約 20%、分數不變；qwen3 加 `/no_think` 沒效果。

## B. 整題連續對話（2 道仿真題、同一個對話一路貼卡）
| 模型 | 4k | 8k |
|---|---|---|
| qwen2.5:14b | 79% | 93～100% |
| gpt-oss:20b | 79% | 71～86% |
| gemma3:12b | 68% | 71～75% |
| qwen3:8b | 79% | 64～71% |
- 4k 時同一個對話貼到第 5～6 張卡就會溢出（Ollama 實際截斷），表格只寫 1～2 列。→ **每做完一小步就開新對話**（開場卡 3/3 狀態卡）。

## C. 參考卡問答（141 張參考卡逐條對照官方來源核對、修正後；190 個案例）
| 模型 | 根據卡回答（軟體 / 硬體） | 卡上沒有 → 「資料中沒有」 |
|---|---|---|
| gpt-oss:20b | 85% / 96% | 97% / 94% |
| qwen3:8b | 86% / 95% | 100% / 94% |
| qwen2.5:14b | 84% / 84% | 100% / 97% |
| gemma3:12b | 78% / 86% | 100% / 100% |
- **貼了參考卡，模型幾乎不會亂編。** 考場上問硬體 / SDK / ROS 的事，一律先貼參考卡再用查詢 1/2。
- 「用參考卡檢查我的程式」（查詢 2/2）比較難：gpt-oss 94～100%，其他 30～60%。卡上的「陷阱句」（例：count 填成 bytes）小模型容易把方向弄反 → 卡片已加「程式真的這樣寫 = 違反」。結果要自己核對。
- 核對時修掉的錯誤事實（節錄）：PIO 用 pico2 建置不需要手寫 `.pio_version 1`；`queue_init` 回傳 void；共用 IRQ handler 上限 4（不是 6）；Hazard3 預設 `-march` 與 SDK 不加 `-mstrict-align`；ROS 2 型別不合通常沒有 WARN；跨容器要 `--ipc host`；FreeRTOS RP2350 port 用 doorbell 不是 FIFO、`sleep_ms` 讓出 CPU 是 SYNC_INTEROP。

## 總結：考試當天怎麼用
1. 開新對話 → 開場卡 1/3（要改範本再加範本 1/7）。
2. 問硬體 / SDK / ROS 的事：**先貼對應參考卡**（模型回「收到」）→ 查詢 1/2。各模型「卡上沒有 → 資料中沒有」94～100%。
3. 數字、byte、cycle、指令欄位：**用工具算**（`frame.py diff`、PIO 檢查、RISC-V 解碼 one-liner），模型只照抄和比對。
4. 每做完一小步就用狀態卡開新對話。
5. 偏弱的卡（實作、量測、push 前檢查、檢查程式 2/2）：結果一定自己核對。
