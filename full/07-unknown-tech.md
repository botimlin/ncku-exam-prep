# 07 陌生技術速學流程

> 用途：備援。題目用到工具包完全沒涵蓋的技術（新的框架、晶片、周邊、函式庫、語言、工具）時，在 30–60 分鐘內建立「夠用的」理解並開始動手。
> 核心想法：不是學會整個技術，而是**只學到能解這題的程度**。
> 最後更新：2026-11

---

## 0. 心態

1. **目標是「能動 + 能改」，不是「全懂」。** 考試只需要你理解題目會碰到的那一小塊。
2. **先跑起來再讀。** 能編譯、能執行的最小範例，比讀十頁文件更快建立直覺。
3. **找相似物。** 幾乎所有新技術都像某個你已經懂的東西（「這個 queue 就是 ROS topic」「這個周邊就是 DMA 加狀態機」）。先用類比建立骨架，再修正差異。
4. **題目附的文件與程式碼是最可靠的資料。** 它們就是出題者想讓你讀的；網路上的資料可能版本不同。
5. **時間盒（timebox）。** 每個階段設時間上限，超過就往下走或求助。

---

## 1. 五步速學法

```
① 定位（5 分）   這是什麼？解決什麼問題？在系統中的哪個位置？
② 跑起來（15 分）找到最小範例 → 編譯 → 執行 → 看到輸出
③ 建模型（15 分）核心概念、資料流、生命週期、主要 API 的 5–10 個
④ 小改動（10 分）改範例一個參數 → 預測結果 → 驗證預測
⑤ 對準題目（10 分）把學到的東西對應到題目要你改的地方
```

### ① 定位：回答這 6 個問題

| 問題 | 為什麼 |
|---|---|
| 它是什麼類別的東西？（函式庫 / 框架 / 硬體周邊 / 協定 / 工具 / 語言）| 決定學習方式 |
| 它解決什麼問題？沒有它會怎樣？ | 理解設計動機 |
| 它的輸入、輸出是什麼？ | 建立黑盒子模型 |
| 在本題系統裡，它跟誰互動？ | 定位在架構圖中的位置 |
| 它像我已經懂的什麼東西？ | 借用既有知識 |
| 版本是什麼？ | 網路資料與實際環境可能不同 |

### ② 跑起來：找最小範例的地方（依優先順序）

1. 題目附的範例、測試程式、`examples/` 資料夾。
2. 專案中已經使用這個技術的程式碼（`grep -rn "關鍵字" .`）。
3. 官方文件的 Getting Started / Quick Start / Hello World。
4. 官方 GitHub repo 的 `examples/`、`tests/`、`README`。
5. 標頭檔或原始碼本身（API 註解常比文件準）。

找到後：**原封不動先跑一次**，確認環境沒問題，再改。

### ③ 建模型：要畫出的東西

```
【技術名稱】心智模型
一句話：它是 ___，用來 ___。
類比：像 ___，差別在 ___。

核心概念（3–7 個名詞）：
  - 名詞 A：___
  - 名詞 B：___
概念之間的關係：A 包含 B / A 產生 B / A 透過 B 傳給 C

生命週期 / 使用順序：
  初始化 → 設定 → 啟動 → 運作（迴圈 / 事件）→ 結束 / 釋放

最重要的 API（5–10 個，附用途）：
  - xxx_init()：
  - xxx_config()：
  - ...

限制與規則：（資源數量、對齊、執行緒安全、阻塞與否、單位）
常見陷阱：
```

幾乎所有系統類技術都符合「**初始化 → 設定 → 啟動 → 等待 / 處理 → 釋放**」的節奏（例如 DMA：claim channel → configure → start → wait → release；ROS 2 node：init → create pub/sub → spin → shutdown）。先套這個框架去找對應的 API。

### ④ 小改動：用預測驗證理解

- 改一個參數（大小、頻率、數量、模式）。
- **改之前先寫下預測**：輸出會變成什麼？
- 跑完比對。預測對 → 模型正確；預測錯 → 這裡就是理解有誤的地方，回頭查。

### ⑤ 對準題目

- 題目要改的地方用到了這個技術的哪些概念與 API？
- 有沒有效能相關的設定（buffer 大小、批次、模式、硬體加速選項）？
- 回到 `02-read-spec.md` 更新架構圖，回到 `03-optimize.md` 繼續做。

## 2. 依技術類別的速學重點

| 類別 | 先找 | 重點問題 |
|---|---|---|
| **硬體周邊** | datasheet 該章的 Overview、方塊圖、Programmer's model、SDK 範例 | 暫存器怎麼設定？有沒有 FIFO / DMA / 中斷？時脈從哪來？資源有幾個？ |
| **函式庫 / SDK** | header 檔、範例、API 文件 | 初始化順序？阻塞還是非阻塞？誰負責記憶體？執行緒安全嗎？回傳值代表什麼錯誤？ |
| **框架**（如 ROS 2）| 架構概念頁、教學、CLI 工具 | 誰呼叫誰（控制反轉）？callback 在哪個執行緒？設定檔在哪？ |
| **通訊協定** | 封包格式、狀態機圖 | 框架（frame）怎麼界定？錯誤偵測？流量控制？位元組順序？ |
| **工具**（建置 / 除錯 / 分析）| `--help`、`man`、範例指令 | 最常用的 5 個指令？輸出怎麼解讀？ |
| **語言**（不熟的語言）| 語法速查、跟熟悉語言的對照 | 型別系統？記憶體管理？錯誤處理？怎麼編譯 / 執行？ |
| **檔案格式 / 設定檔** | 範例檔、schema | 哪些欄位必填？預設值？改了哪個會影響效能？ |

### 2.1 讀陌生 header 檔的方法

```bash
grep -n "^[a-z].*(" include/xxx.h | head -50        # 粗略列出函式宣告
grep -n "typedef\|struct\|enum" include/xxx.h       # 資料型別
grep -n "@brief\|\\\\brief\|/\*\*" include/xxx.h | head   # 文件註解
grep -rn "xxx_init\|xxx_start" examples/ src/       # 這些 API 在哪被用
```

看 header 時優先看：`init` / `create` / `config` / `start` / `stop` / `deinit` 系列，以及所有 `struct` / `enum` 定義。

### 2.2 讀陌生 datasheet 章節

1. 看章節目錄，找跟題目相關的小節。
2. 看方塊圖：資料從哪進、從哪出、經過哪些單元。
3. 看 Programmer's model / Operation：操作順序。
4. 暫存器表只看會用到的欄位。
5. 搜尋 "must"、"note"、"caution"、"errata"、"not supported"。

### 2.3 讀陌生程式碼庫

1. `README` → 建置設定（CMakeLists / Makefile / package.xml）→ 進入點。
2. 看目錄結構推測模組劃分。
3. `git log --oneline` 看最近改了什麼（如果有歷史）。
4. 從進入點沿著主流程往下讀，遇到不懂的函式先猜它做什麼，不要立刻深入。

## 3. 給模型的速學提示範本

### 3.1 定位

```
/解釋
題目用到 {{技術名稱}}（版本 {{版本}}）。我完全沒用過。
請用 10 行以內告訴我：
1. 它是什麼類別的東西、解決什麼問題
2. 它像我熟悉的哪個東西（我熟：{{熟悉的技術}}），差別在哪
3. 核心概念 3–7 個，以及它們的關係
4. 典型使用流程（初始化 → … → 釋放）
5. 最常見的 3 個陷阱
不確定的地方請標【推測】。
```

### 3.2 解讀範例

```
/走讀
這是 {{技術名稱}} 的官方最小範例。請逐段解釋每一行在做什麼，
並標出：哪些是必要步驟、哪些是可選設定、哪些參數會影響效能。

{{貼範例}}
```

### 3.3 API 地圖

```
以下是 {{技術名稱}} 的 header 檔（或 API 文件）。
請整理成表格：函式名、用途、是否阻塞、重要參數、回傳值意義。
依「使用順序」排列，並標出解這題最可能需要的 5–10 個。
只列出原文中確實存在的函式。

{{貼 header 或文件}}
```

### 3.4 驗證理解

```
我對 {{技術名稱}} 的理解如下：
{{寫下你的心智模型}}
請指出錯誤或遺漏的地方，並給我一個小實驗（改一個參數）來驗證我的理解。
```

### 3.5 對準題目

```
我已經大致懂 {{技術名稱}}。題目要求：{{題目要求}}。
相關程式碼：{{貼程式碼}}
請說明：
1. 題目要改的地方用到了這個技術的哪些概念 / API
2. 這個技術提供了哪些可能用來優化的選項（模式、硬體加速、批次、buffer 設定）
3. 建議的第一步
```

## 4. 時間管理

| 階段 | 上限 | 超過時 |
|---|---|---|
| 定位 | 5 分 | 直接跳到找範例 |
| 跑起來 | 15–20 分 | 環境問題 → 舉手問監考；範例找不到 → 從專案現有程式碼下手 |
| 建模型 | 15 分 | 先用「初始化 → 設定 → 啟動 → 處理 → 釋放」框架硬套，邊做邊修正 |
| 小改動 | 10 分 | 跳過，直接對準題目 |
| 整體 | 60 分 | 評估是否先做其他題目，有時間再回來 |

**如果這個陌生技術只佔題目一小部分**，先把它當黑盒子用（照範例的方式呼叫），把時間花在其他部分。

## 5. 常見錯誤

| 錯誤 | 預防 |
|---|---|
| 從頭讀完整份文件 | 只讀跟題目相關的段落 |
| 參考網路上不同版本的資料 | 先確認版本；以題目附的文件與實際 header 為準 |
| 沒跑範例就開始寫 | 先跑起來確認環境 |
| 相信模型說的 API | `grep` header 確認存在 |
| 一次學太多概念 | 只學題目需要的 3–7 個核心概念 |
| 不寫下心智模型 | 寫不出來的地方就是不懂的地方 |
