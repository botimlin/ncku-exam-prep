## 2. 建議時間配置

| 時段 | 目標 | 產出 |
|---|---|---|
| 09:00–09:10 | 聽說明，記下所有規則、評分方式、提交方式 | 筆記 |
| 09:10–09:20 | 開好模型對話（貼 `01-context.md`）、盤點專案檔案 | 檔案清單 |
| 09:20–10:00 | 讀題 → 題目理解卡；**所有題目都先看過一遍** | 每題的理解卡、難度與分數評估 |
| 10:00–10:30 | 跑 baseline、確認工具鏈能編譯、能提交 | baseline 分數 |
| 10:30–12:00 | 先做「最確定能拿分」的部分 | 至少一次有分數的提交 |
| 12:00–12:30 | 吃飯、休息，**真的休息** | — |
| 12:30–13:00 | 回顧上午狀態，`/摘要` 更新狀態卡，排下午優先順序 | 下午計畫 |
| 13:00–15:30 | 主要優化工作 | 多次有效提交 |
| 15:30–16:00 | 檢查點：評估剩餘方案，砍掉做不完的 | 決定最後衝刺目標 |
| 16:00–16:30 | 收尾：最佳版本確認提交、`05-submit-check.md` 檢查 | **最佳版本已提交** |
| 延長時間 | 若有延長，再挑低風險的改進 | — |

### 2.1 多題時的分配

- 先全部看過，評估「分數 / 預估時間」，從 CP 值最高的開始。
- 每題先拿基本分（能正確執行、通過正確性），再回頭優化。
- 不要在一題卡到底而其他題完全沒碰。
- 依考前練習推測，可能有 ROS 2、位元運算 / PIO / RISC-V、臨界區 / DMA 等子題，彼此可能相關也可能獨立——以實際題目為準。

## 3. 決策規則

| 情況 | 做法 |
|---|---|
| 同一問題卡 20 分鐘 | 寫錯誤回報問模型，或換方法 |
| 同一問題卡 40 分鐘 | 回到上一個能用的版本，改做別的 |
| 某方案預估要 2 小時以上 | 先做其他較短的方案；有剩時間再回來 |
| 15:30 之後 | 不開始高風險的大改動 |
| 16:00 之後 | 只做收尾與確認提交 |
| 模型回答開始變差 | `/摘要` → 開新對話 → 貼開場設定 + 狀態卡 |
| 環境 / 設備問題 | 立刻舉手問監考，不要自己修系統 |

---

## 4. 晤談（15:00–18:00）

- 是選擇性的「了解系上特色」，不在考試流程中。
- 若作答時間仍在進行，要權衡：晤談會佔用作答時間。可在確定提交最佳版本後、或延長時段前後再去。
- 想問的問題可以事先準備（例如系上的嵌入式 / 系統相關研究、大一課程）。
