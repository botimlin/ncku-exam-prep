# 效能優化（精簡版）

## 鐵則
正確性第一｜先量測｜只優化瓶頸｜一次改一處｜有效就 commit｜用評分相同條件量（Release、同規模）

Amdahl：加速比 = 1 / ((1-p) + p/s)；p = 該段佔比。p=0.6 時上限 2.5×。

## 流程
baseline（正確輸出 + 效能，多次取中位數）→ 剖析各段耗時 → 分類瓶頸 → 列方案（收益 / 風險 / 時間）→ 改一處 → diff 驗證 + 量測 → 保留或回復 → 重來

紀錄表：`# | 時間 | 改動 | 正確? | 效能 | 倍數 | 保留? | commit`

## 量測
- Linux：`clock_gettime(CLOCK_MONOTONIC)` 包住區段，輸出到 stderr；`time ./prog`
- RP2350：`time_us_64()` 前後相減；短區段重複 N 次；printf 放區段外（USB stdio 很慢）
- ROS 2：`ros2 topic hz / bw / delay`
- 陷阱：量到 debug 版、結果沒用被編譯器刪掉（用 volatile 接）、冷啟動

## 瓶頸判斷
| 現象 | 類型 |
|---|---|
| CPU 滿、時間 ∝ 運算量 | 運算 |
| 資料大、存取跳躍 | 記憶體 / 匯流排 |
| CPU 閒但慢 | I/O / 通訊等待 |
| 加執行緒沒變快 | 鎖競爭 / false sharing |
| 輸入稍大時間暴增 | 演算法 |

## 手法（收益大 → 小）
1. 演算法：降複雜度、換資料結構、快取 / 查表、提早結束
2. 卸載與平行：DMA 搬資料｜PIO 處理時序 I/O 與位元打包｜第二核心分工或管線｜雙緩衝讓計算與搬運重疊
3. 同步：臨界區縮到最短（計算移出鎖外）｜各自累計最後合併｜原子操作取代鎖｜避免 false sharing
4. 記憶體：循序存取｜熱碼放 SRAM（`__not_in_flash_func`）｜對齊、32 位元寬讀寫｜熱路徑不 malloc
5. I/O：批次處理｜移除熱路徑 printf｜ROS 2 callback 不阻塞
6. 微優化：2 的冪次用位移 / 遮罩｜Hazard3 無 FPU，float 改定點數｜branchless｜展開迴圈｜`__builtin_popcount/clz/ctz`
7. 編譯器：-O2 / -O3 / -Os｜inline、restrict、const｜看 `.dis` / objdump（先確認評分是否允許改旗標）

## 方案選擇
時間少時選「中收益、低風險、15 分內」；小改動累積勝過沒做完的大改動；有效就提交讓分數落袋。

## 驗證
`diff expected.txt actual.txt`｜測空、最小、最大、非 4 倍數長度、不對齊｜多執行緒跑數十次看是否一致

## 反模式
沒量就改｜一次改很多｜破壞正確性｜優化非熱點｜量錯版本｜賭兩小時高風險方案｜不記錄｜改到評分介面
