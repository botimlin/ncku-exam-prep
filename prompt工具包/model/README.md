# model/：給考場模型的說明書（操作者使用說明）

> **這是考場主流程**（[`../../考場SOP.md`](../../考場SOP.md)）：每個對話開頭貼總說明 1/3～3/3，模型看題目前就知道你有什麼；看完題目後由模型用【要資料】/【要卡】跟你要。`cards/` 的開場 1/3 是 context 太小時的手動模式。

> **2026-11-14 實測後更新**：這份描述的是「開題對話」（看懂題目、選範本，讓模型用【要卡】/【要資料】跟你要）。**改程式不要用這套來回**，改用 `../../考場SOP.md` §5.2 的修 bug 專用對話（G01-01 → 題目 → 檔案 → 陷阱卡 → G04-01 檢查卡 → G05-01 修改卡）：實測 gemma4:12b 照著改完能用 0/5 → 4/5。


考場的小模型看不到你的檔案，也不知道你手上有什麼。這個資料夾讓模型知道：

1. **自己的角色和規則**（`00-總說明.md`）。
2. **你手上有哪些資料**：所有卡片的名稱清單（`01-資源目錄.md`），加上預製範本的細節規格（`spec-*.md` 規格卡）。
3. **怎麼跟你要**：模型在回答最後寫【要資料】（考場、終端機、題目的東西）或【要卡】（工具包的卡），你照下面兩張對照表去拿，貼回去。
4. **考場上要跟你要什麼**：每種狀況要哪些資料、你要跑什麼指令（`02-要資料.md`）。

跟 `../cards/` 的關係：`cards/` 是「你貼一張卡，模型照格式做一件事」；`model/` 是「模型自己說它需要哪張卡、哪段程式、哪個指令的輸出」。兩套用**同一個協定**（訊息分 資料 / 提示卡 / 一般問題；缺東西用【要資料】/【要卡】），規則卡二選一（總說明 1/3 或開場 1/3，不要一起貼）；模型要的提示卡、參考卡都在 `cards/`。

> 這一套**沒有用 GPU 跑過壓力測試**（`cards/` 有）。卡片寫法沿用壓力測試學到的 25 條規則（`../README.md`）。規格卡的內容來自 `../../預製程式碼/說明書/`（2026-11-12～13 逐行核對、實測過的版本），行號以 commit 當時的程式為準。

## 步驟

**開頭（每個新對話都一樣，模型還沒看到題目）**
1. 貼 G01-01（總說明 1/3）→ 了解。
2. 貼 G01-02（總說明 2/3，工具清單＋編號）→ 了解。
3. 貼 G01-03（總說明 3/3，資料代號）→ 了解。

**第一次：拿到題目**
4. 題目分段貼，每段包在資料區塊裡，第一行寫「題目第 k/N 段」→ 收到。
5. 貼 G02-01（開題）→ 模型寫出小題、評分、最像的範本區，最後 2 行跟你要東西。
6. 理解的部分**存進雲端筆記**（之後每個新對話都會用到）。

**之後的迴圈**
7. 模型寫【要資料】/【要卡】→ 照下一節的表去拿 → 包在資料區塊裡貼回去，**最後一行寫「繼續」**（④ 類訊息；沒寫「繼續」它只會回「收到」）。
8. 模型要的是提示卡 → 把 `{{…}}` 填好，**直接貼、不要包**（② 類訊息）。
9. 模型給 patch 或指令 → 你去改、去跑 → 結果包在資料區塊裡、最後寫「繼續」貼回去。

**換新對話**（任一條成立：模型開始忘規則、表格寫一半、同一個對話已經貼了約 5 張卡）
10. 貼 G03-03（狀態卡）叫它出狀態卡 → 存筆記。
11. 新對話：G01-01、G01-02、G01-03 → 狀態卡（包起來，最後寫「繼續」）。狀態卡「用到的卡」那欄列的卡，模型會再跟你要。

context 很小（開頭 3 張貼完模型就忘了規則）→ 改用手動模式：`cards/00-starter.md` 開場 1/3 ＋ SOP 附錄 B 的表。

## 怎麼回應【要資料】和【要卡】

先看標籤，就知道去哪裡拿：**【要資料】→ 終端機 / 題目頁面**；**【要卡】→ 工具包的 md 檔**。兩種都要時，先給資料。

### 【要資料】：去終端機或題目拿

| 模型寫 | 怎麼拿 |
|---|---|
| `K1`…`S4`（代號） | 照 `02-要資料.md` 那個代號的指令跑，貼結果 |
| `題目第 n 段` | 從題目頁面複製那一段（≤ 1000 字） |
| `程式 <路徑> a-b` | `cat -n <路徑> \| sed -n a,bp`，貼帶行號的結果（預製程式碼或出題 repo 都一樣） |
| `指令 <指令>` | 跑那個指令，貼輸出（超過 60 行只貼前 60 行，並說還有幾行） |

### 【要卡】：用編號到 `../編號卡/` 拿

模型寫的是編號（例 `L02-02`）。看第一個字母開對應的查找檔，**Ctrl-F 編號**，複製「## 編號」下面那張卡：

| 字母 | 查找檔 |
|---|---|
| G 開頭、H 要資料、M 目錄、E 規格卡 | `../編號卡/1-G開頭_H要資料_M目錄_E規格卡.md` |
| A API卡、C 片段卡、F 食譜卡 | `../編號卡/2-A_API卡_C片段卡_F食譜卡.md` |
| Q 提示卡 | `../編號卡/3-Q提示卡.md` |
| L 參考卡 | `../編號卡/4-L參考卡.md` |

- 只寫系列（例 `L02`＋要什麼）→ Ctrl-F `L02-01`，往下看標題挑最符合的一張。
- 寫的是卡名不是編號（例「DMA 參考卡第 2 張」）→ 查 `../編號卡/00-編號總表.md`。
- 編號怎麼定的：`card_index.py`（字母避開資料代號 K B R T P S）。

參考卡、規格卡、API 卡、片段卡、食譜卡是**資料**（包在資料區塊裡，模型回「收到」）；提示卡是**任務**（直接貼，不要包）。**例外：F01-00（食譜卡 優化 0）是任務**，和提示卡一樣直接貼、填好最下面的量測。

貼回去的格式（每次都一樣）：

```text
<<<資料 開始>>>
來源：E01-02
（貼內容）
<<<資料 結束>>>
繼續
```

## 模型要錯、要太多時

| 狀況 | 怎麼做 |
|---|---|
| 模型要的卡片名稱不存在 | 貼「目錄」裡最接近的那張，或回「沒有這張，請看目錄 n」並貼目錄 |
| 一次要超過 2 樣 | 只給前 2 樣，回「其他的下一輪再給」 |
| 要整個檔案 / 超過 60 行 | 先給規格卡（裡面有函式的行號），再請它指定 60 行內的範圍 |
| 一直要、不回答 | 回「資料已經夠了，請直接用現有資料回答，缺的標【推測】」 |
| 拿到資料後又要同一樣 | 它忘了：開新對話，貼「總說明 1/3～3/3（G01-01～03）+ 狀態卡 + 那份資料」 |
| 改了程式之後行號對不上 | 規格卡的行號是考前版本；你改過的檔案用 `grep -n "函式名" 檔名` 找新行號再貼 |
| 貼了題目片段，它開始分析或跟你要東西 | 回「這是 ① 類訊息（只有資料），只回覆『收到』」；再犯就開新對話 |
| 貼了它要的東西，它只回「收到」 | 你忘了最後一行「繼續」：補一則「繼續」 |
| 題目和卡片說法不同 | 照優先順序：題目原文 > 考場 header、指令輸出 > 卡片 > 模型記憶 |
| 模型說的 API、暫存器和卡片不同 | 以卡片和考場 header 為準（`cards/08-docs-map.md` 有網址） |

## 為什麼這樣設計

- **名稱要照抄**：小模型會把「DMA 參考卡第二張」講成各種說法，你很難找。所以卡片名稱固定成「系列名 + 號碼」，目錄裡列出全部名稱，模型照抄。
- **先規格卡、再程式**：整個檔案貼不下；規格卡告訴模型函式在哪幾行，它只要那幾行。
- **資料用代號**：「把錯誤訊息貼給我」太模糊，你會貼太多或太少；代號對應到固定的指令和長度。
- **一次最多 2 個請求**：多了你來回找東西的時間比模型回答還久，而且小模型的 context 會爆。
