RP2350（Pico 2），非 RP2040。pico-sdk 2.x。
```cmake
cmake_minimum_required(VERSION 3.13)
set(PICO_BOARD pico2 CACHE STRING "Board type")
# RISC-V：set(PICO_PLATFORM rp2350-riscv CACHE STRING "Platform")
include(pico_sdk_import.cmake)        # 必須在 project() 之前
project(my_app C CXX ASM)
pico_sdk_init()                       # project() 之後、add_executable 之前
add_executable(my_app main.c)
target_link_libraries(my_app pico_stdlib hardware_dma hardware_pio hardware_clocks)
pico_generate_pio_header(my_app ${CMAKE_CURRENT_LIST_DIR}/foo.pio)
pico_enable_stdio_usb(my_app 1)       # printf 走 USB CDC
pico_enable_stdio_uart(my_app 0)      # printf 走 UART0（GPIO0/1）
pico_add_extra_outputs(my_app)        # .uf2 / .bin / .hex / .dis
```
- `cmake .. -DPICO_BOARD=pico2`（Arm）；RISC-V 加 `-DPICO_PLATFORM=rp2350-riscv`；`make -j`。
- **沒設 board/platform → 預設 rp2040 + pico，Pico 2 不能跑**。cmake 輸出應有 `Target board (PICO_BOARD) is 'pico2'`。
- 換 board/platform 要 `rm -rf build`（cache 記住舊值）。
- 沒有 `pico2_riscv` 這個 board；`rp2350` = `rp2350-arm-s`（預設 Arm Secure）。
- `PICO_BOARD`/`PICO_PLATFORM` 要在 include(pico_sdk_import.cmake) 之前設，或用 -D 傳。

## L01-02

【參考卡｜RP2350 pico-sdk 2/8｜建置類型、輸出檔、燒錄】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）。`pico_stdlib` **不含** `hardware_dma`、`hardware_pio`、`pico_multicore`，要自己 link，否則找不到標頭 / undefined reference。
Build type：
- `Release`（**SDK 預設**）：`-O3 -DNDEBUG`，SDK 另加 `-g`。量效能、交卷用。`NDEBUG` 會讓 assert 失效。
- `Debug`：`-Og -g`（`PICO_DEOPTIMIZED_DEBUG=1` 改 `-O0`）。`MinSizeRel`：`-Os`。`RelWithDebInfo`：`-O2 -g`。
- 與 judge 使用相同 build 設定；題目給 CMakeLists 就照抄。
Binary type（`pico_set_binary_type(target X)`）：
- `default`：在 flash 經 XIP cache 執行；cache miss 時慢。
- `copy_to_ram`：存在 flash，開機整份複製到 SRAM 執行；快、佔 SRAM、重開機仍在。
- `no_flash`：只載入 SRAM，斷電就沒了。
- 全域：`-DPICO_DEFAULT_BINARY_TYPE=copy_to_ram`。`blocked_ram` 是 RP2040 專用。
輸出檔：`.elf`（gdb、objdump、nm）、`.uf2`（拖進 BOOTSEL）、`.dis`（反組譯）、`<target>.elf.map`（位址與大小）。
燒錄：
- BOOTSEL：按住 BOOTSEL 插 USB → 出現磁碟機（名稱 `RP2350` ⚠️未在官方文件原文確認）→ 複製 `.uf2`。
- `picotool load -x my_app.uf2`（`-x` 燒完執行，`-v` 驗證，`-f` 讓有 USB stdio 且仍在跑的板子先自動重開進 BOOTSEL；程式卡死時 `-f` 無效）。
- `picotool info -a`、`picotool reboot -u`（進 BOOTSEL）、`picotool reboot -c riscv|arm`（選架構）。

## L01-03

【參考卡｜RP2350 pico-sdk 3/8｜晶片總覽與 RP2040 差異】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Raspberry Pi Pico 2 = RP2350A），**不是 RP2040**。RP2040 數值放括號。
- CPU：雙核 Cortex-M33 **或**雙核 Hazard3 RISC-V（開機選，同時只用一種）（RP2040：雙核 M0+）
- 預設 clk_sys 150 MHz（125）；XOSC 12 MHz
- SRAM 520 KB，10 bank（264 KB）；Boot ROM 32 KB（16 KB）；XIP cache 16 KB
- PIO：3 block × 4 SM = 12 SM（2×4）
- DMA：16 channel、4 條 IRQ（12 / 2）
- PWM 12 slice（8）；Timer：TIMER0+TIMER1 各 4 alarm（1 個 timer）
- UART/SPI/I2C 各 2；IRQ 數 52（32）
- 沒有 RP2040 的 SIO 除法器周邊（`hardware_divider` 在 RP2350 是軟體）；CPU 有除法指令，直接寫 `/`
- 浮點：M33 單精度 FPU + DCP 加速 double；**Hazard3 無 FPU** → 用固定點（RP2040 無 FPU）
- 新增：HSTX、TRNG、SHA-256、8 KB OTP、TrustZone、POWMAN
- GPIO：RP2350A 30 支、RP2350B 48 支
- Pico 2 板：LED = GPIO25（Pico 2 **W** 的 LED 在無線晶片，要 `cyw43_arch`）、4 MB flash、uart0 TX/RX = GPIO0/1、i2c0 SDA/SCL = GPIO4/5、spi0 RX/CSn/SCK/TX = GPIO16/17/18/19
- RP2350 pad 重置後是隔離（ISO）狀態，要經 `gpio_init` / `gpio_set_function` 才會動；直接寫 IO_BANK0 不呼叫 SDK 時腳可能沒反應
- ⚠️ RP2350-E9（A2 stepping；A4 已修）：輸入用內部 pull-down 可能異常 → 讀按鍵用 pull-up + 接地按鈕
- IRQ 編號與 RP2040 不同，一律用名稱（`DMA_IRQ_0`=10、`PIO0_IRQ_0`=15、`UART0_IRQ`=33）；RP2040 的 `TIMER_IRQ_0` 在 RP2350 叫 `TIMER0_IRQ_0`

## L01-04

【參考卡｜RP2350 pico-sdk 4/8｜記憶體映射與擺放巨集】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）位址（RP2040 不同，勿混用）：
- ROM `0x00000000`（32 KB）；XIP flash（cached）`0x10000000`；XIP 不經 cache `0x14000000`
- SRAM `0x20000000`–`0x2007FFFF`：SRAM0–7 共 512 KB striped（SRAM0–3 起 0x20000000、SRAM4–7 起 0x20040000）
- SCRATCH_X `0x20080000`（4 KB，core 1 stack）、SCRATCH_Y `0x20081000`（4 KB，core 0 stack）
- APB `0x40000000`；AHB `0x50000000`（DMA 0x50000000、PIO0/1/2 0x50200000/0x50300000/0x50400000）；SIO `0xD0000000`；PPB（M33 NVIC/DWT）`0xE0000000`
- 原子別名：+0x1000 XOR、+0x2000 SET、+0x3000 CLR → `hw_xor_bits/hw_set_bits/hw_clear_bits(&reg, mask)`。SIO 不支援，GPIO 用 `sio_hw->gpio_set/gpio_clr/gpio_togl = mask`
- 預設 stack **每核 2 KB**（`PICO_STACK_SIZE=0x800`）→ 大陣列用 static/全域
擺放巨集：
- `void __not_in_flash_func(hot)(int n) {...}`：函式放 RAM（不阻止 inline，被 inline 進 flash 函式就跟著在 flash）
- `__time_critical_func(f)` 預設同上；`__no_inline_not_in_flash_func(f)` 放 RAM 且不 inline
- `static const uint32_t __not_in_flash("tbl") lut[256] = {...};`：資料放 RAM（const 也行）
- `uint32_t __scratch_x("buf") buf[256];`：放 scratch（需字串參數；會與 stack 搶空間）
- `const` 全域陣列預設在 flash；熱查表搬 RAM
- 檢查 `build/my_app.elf.map` 或 `arm-none-eabi-nm -n`：0x10… = flash、0x20… = RAM

## L01-05

【參考卡｜RP2350 pico-sdk 5/8｜計時與效能量測】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：預設 clk_sys 150 MHz → `time_us_*` 解析度 1 µs = 150 cycles。
原則：Release、先印 `clock_get_hz(clk_sys)`、暖機、重複 N 次取 min/中位數、區段內不 printf、結果寫 `volatile` sink（被測陣列本身不要 volatile）。短函式跑 1000 次再除。
```c
static volatile uint32_t sink;
sink = work();                                    // 暖機
uint64_t t0 = time_us_64();
sink = work();
uint64_t t1 = time_us_64();
uint32_t us = (uint32_t)(t1 - t0);
```
Cortex-M33 cycle counter（DWT）：
```c
#include "hardware/structs/m33.h"
m33_hw->demcr     |= M33_DEMCR_TRCENA_BITS;
m33_hw->dwt_cyccnt = 0;
m33_hw->dwt_ctrl  |= M33_DWT_CTRL_CYCCNTENA_BITS;
uint32_t c0 = m33_hw->dwt_cyccnt; f(); uint32_t dc = m33_hw->dwt_cyccnt - c0;
```
（150 MHz 約 28.6 秒溢位；SDK 預設 Secure 模式下可用 ⚠️未在實機驗證）
Hazard3 RISC-V：讀 `mcycle`/`mcycleh` CSR；**計數器預設停止**（`mcountinhibit` reset 值 0x5），量測前必須 `csrci mcountinhibit, 5`，否則讀數永遠不變。
- `time_us_32` 約 71.6 分鐘溢位，用 `time_us_64`。
- 中斷干擾：`uint32_t s = save_and_disable_interrupts(); ... restore_interrupts(s);`（關太久 USB 可能斷線）。
- 比預期慢：Debug build、flash cache miss、RISC-V 用 float/double、隱性 double（`0.5` 是 double，寫 `0.5f`）、clk_sys 不是你以為的值。
- 150 MHz 下 1 ms = 150,000 cycles。

## L01-06

【參考卡｜RP2350 pico-sdk 6/8｜stdio 與 GPIO 陷阱】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2），pico-sdk 2.x。
```c
#include <stdio.h>                       // printf 要自己 include（pico/stdlib.h 不含）
#include "pico/stdlib.h"
int main(void) {
    stdio_init_all();
    while (!stdio_usb_connected()) sleep_ms(10);   // 需要時才等
    printf("hello %d\n", 42);
    int c = getchar_timeout_us(100000);  // 逾時回 PICO_ERROR_TIMEOUT（用名稱比較）
    if (c != PICO_ERROR_TIMEOUT) putchar(c);
    stdio_flush();
}
```
- USB CDC：`stdio_usb_connected()` 看主機的 **DTR**；**未連線時輸出直接丟掉**，主機停止讀取 500 ms 後也丟。開機到主機開 port 之間的 printf 會消失 → 等 `stdio_usb_connected()` 或開頭 `sleep_ms(2000)`。
- 換行：judge 逐字比對時確認 `\n` 與 CRLF 轉換（`PICO_STDIO_DEFAULT_CRLF`）。
- printf 慢，不放計時區段或 ISR。`main` 不要 return，最後 `while (true)`。
- 開 `pico_enable_stdio_uart` 時 stdio 占用 uart0（GPIO0/1）。
GPIO：
```c
gpio_init(25); gpio_set_dir(25, GPIO_OUT); gpio_put(25, 1);
gpio_init(15); gpio_set_dir(15, GPIO_IN); gpio_pull_up(15);
gpio_set_function(2, GPIO_FUNC_PIO0);   // RP2350 另有 GPIO_FUNC_PIO2
sio_hw->gpio_togl = 1u << 25;            // 直接寫 SIO
```
- `gpio_init` 後輸入腳仍是 reset 的 pull-down。
- GPIO 中斷：`gpio_set_irq_enabled_with_callback(15, GPIO_IRQ_EDGE_FALL, true, &cb)`。

## L01-07

【參考卡｜RP2350 pico-sdk 7/8｜時脈、時間 API、中斷】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：預設 clk_sys 150 MHz（RP2040 125 MHz），`clock_get_hz(clk_sys)` 取實際值（link `hardware_clocks`）。
- `set_sys_clock_khz(khz, required)`：只接受 PLL 能精確產生的頻率；回 false 表示沒變；required=true 無法達成會 panic。
- 呼叫後 SDK 把 `clk_peri` 改接 48 MHz（PLL_USB）→ **先改時脈，再 `stdio_init_all()` / `uart_init`**，否則鮑率錯。
- 電壓預設 `VREG_VOLTAGE_1_10`；超過額定 150 MHz 不保證穩定，題目沒允許不要靠超頻。
時間 API：
- `time_us_32()`、`time_us_64()`、`get_absolute_time()`、`absolute_time_diff_us(from, to)`
- `sleep_ms/sleep_us`：**ISR 內不可呼叫**；`busy_wait_us/ms` 忙等
- `add_alarm_in_ms(ms, cb, ud, fire_if_past)`：cb 回 0 不重複、>0 從現在再等 µs、<0 從上次預定時間起算
- `add_repeating_timer_ms(delay, cb, ud, &timer)`：cb 回 true 繼續；**delay<0 = 固定週期**（start-to-start），>0 = 結束到開始的間隔；`repeating_timer_t` 要 static
- callback 在 IRQ context（預設 core 0）：不可 printf/sleep
中斷：
```c
irq_set_exclusive_handler(DMA_IRQ_0, my_handler);
irq_set_priority(DMA_IRQ_0, PICO_HIGHEST_IRQ_PRIORITY); // 數值越小越優先
irq_set_enabled(DMA_IRQ_0, true);
```
- 預設優先權 0x80；RP2350 高 4 bit 有效（RP2040 高 2 bit）。
- ISR：先清週邊旗標（否則一直重進）、要短、共享變數 `volatile`；時間關鍵 ISR 用 `__not_in_flash_func` 放 RAM。

## L01-08

【參考卡｜RP2350 pico-sdk 8/8｜除錯清單】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2），pico-sdk 2.x。
編譯 / CMake：
- `PICO_SDK_PATH` 未設 / 找不到 `pico_sdk_import.cmake` → export 路徑；從 `$PICO_SDK_PATH/external/` 複製。
- `pico_sdk_init` 未知指令 → include 要在 `project()` 前，`pico_sdk_init()` 在 `project()` 後。
- `hardware/dma.h: No such file` 或 `undefined reference` → 漏 link `hardware_dma`（pio、multicore、clocks 同理）。
- `foo.pio.h` 找不到 → 沒呼叫 `pico_generate_pio_header`。
- 編出 RP2040 程式 → 沒設 `-DPICO_BOARD=pico2`，並 `rm -rf build`。
- `region RAM overflowed` / `SCRATCH_Y overflowed` → 資料太大或 scratch 放太多。
- RP2040 名稱不存在（`TIMER_IRQ_0` 等）→ 改 RP2350 名稱。
- TinyUSB submodule 未初始化 → SDK 目錄 `git submodule update --init`，或改 UART stdio。
沒有輸出：
1. 確認是 RP2350 build；2. `pico_enable_stdio_usb(target 1)` + `stdio_init_all()`；3. USB 太早印（等 `stdio_usb_connected()`）；4. UART：GPIO0/1、115200、改時脈後重新 init；5. `main` return 了；6. Pico 2 W 的 LED 不在 GPIO25。
卡住 / 當機：
- 一進函式就掛 → stack overflow（每核只有 2 KB）→ 大陣列 static。
- 卡等待迴圈 → 旗標沒 volatile、ISR 沒觸發、DMA 沒 start。
- 中斷後不動 → ISR 沒清旗標。
- ISR / alarm callback 裡 `sleep_ms` → 改設旗標。
- 雙核卡死 → spinlock/mutex 沒放。
- 完全沒反應、`picotool -f` 失敗 → 手動 BOOTSEL 重插。
計時怪：0 → 被優化掉；第一次慢 → cache miss（暖機）；飄動 → USB 中斷（取 min）。

## L02-01

【參考卡｜RP2350 DMA 1/8｜標準設定流程與 API】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：16 DMA channel、4 DMA IRQ（RP2040 只有 12/2）。pico-sdk 2.x，`#include "hardware/dma.h"`，CMake link `hardware_dma`（pico_stdlib 不含）。
```c
int ch = dma_claim_unused_channel(true);
dma_channel_config c = dma_channel_get_default_config(ch);
channel_config_set_transfer_data_size(&c, DMA_SIZE_32); // 0/1/2 非 bytes
channel_config_set_read_increment(&c, true);   // 預設 true
channel_config_set_write_increment(&c, true);  // 預設 false!
channel_config_set_dreq(&c, DREQ_FORCE);       // 預設；週邊用其 DREQ
dma_channel_configure(ch, &c, dst, src, n_transfers, true); // 先 dst 後 src
dma_channel_wait_for_finish_blocking(ch);      // 含 barrier
dma_channel_cleanup(ch); dma_channel_unclaim(ch);
```
- `dma_channel_configure(ch, &c, write_addr, read_addr, count, trigger)`：**第 3 參數 = 目的地，第 4 = 來源**（同 memcpy）。
- count 是「傳輸筆數」不是 bytes（bytes = 筆數 × 1/2/4）。
- trigger=false 時用 `dma_channel_start(ch)` 或 `dma_start_channel_mask(mask)` 啟動。
- 其他：`dma_channel_is_busy(ch)`、`dma_channel_set_read_addr/write_addr(ch,p,trig)`。
- fill（memset）：read_increment=false，src 指向 static pattern 變數。

## L02-02

【參考卡｜RP2350 DMA 2/8｜預設值與陷阱】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）DMA：TRANS_COUNT 低 28 bit=次數、高 4 bit=MODE（RP2040 是 32 bit 全為次數）。
`dma_channel_get_default_config(ch)` 預設：
- read increment = **true**；write increment = **false**
- DREQ = `DREQ_FORCE`（全速）；chain_to = 自己（不 chain）
- data size = `DMA_SIZE_32`；ring 關
- bswap / irq_quiet / high_priority / sniff = false；enable = true
→ 記憶體到記憶體 memcpy 一定要再 `channel_config_set_write_increment(&c, true)`。
`DMA_SIZE_8/16/32` = 0/1/2（log2，不是 bytes 數）。
陷阱（依頻率）：
1. count 填成 bytes → 搬 2/4 倍、蓋掉後面記憶體。用 `count_of(arr)`（元素數），不要 `sizeof(arr)`。
2. 參數順序：dst 在前、src 在後。
3. 忘開 write_increment → 結果 dst[0] = src 最後一筆，其餘不變。
4. 位址須對齊 data size；硬體**不檢查**，未對齊 = 未定義。
5. buffer / pattern 是區域變數 → 返回後 stack 被重用。用 static/全域。
6. 通道 BUSY 時再觸發被**靜默忽略**；BUSY 時改位址會改到進行中的傳輸。
7. IRQ 沒 acknowledge → handler 不斷重入卡死。
8. count 必須 < 2^28，否則高位被當 MODE；`dma_encode_transfer_count(n)`（2.2+）只做遮罩，不會讓更大的 n 合法 → 拆段或 chain。
9. `dma_channel_unclaim` 不會停通道；先 `dma_channel_cleanup`。
10. 8/16-bit 寫 IO 暫存器會被複製到整個 32 bit。
11. 從 RP2040 搬程式：IRQ 號、DREQ 號、通道數不同，一律用巨集。

## L02-03

【參考卡｜RP2350 DMA 3/8｜練習 transfer engine → pico-sdk 對照】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：16 DMA channel（RP2040 12）。考前練習 section2-3 的 transfer engine 模仿 DMA，對照：
- `ENGINE_CHANNELS 4` → `NUM_DMA_CHANNELS`（16）；通道用完要還
- `engine_claim()` 滿回 -1 → `dma_claim_unused_channel(false)` 回 -1（`true` 則 panic）
- `.dst` / `.src` → `dma_channel_configure` 第 3 參數 write_addr / 第 4 參數 read_addr（dst 在前）
- `.count`（筆數）→ 第 5 參數，同樣是筆數；填 bytes = 搬 2/4 倍
- `.size = XFER_8/16/32`（值 1/2/4）→ `DMA_SIZE_8/16/32`（值 **0/1/2**）
- `.src_increment` → `channel_config_set_read_increment`，預設 true

## L02-05

【參考卡｜RP2350 DMA 5/8｜chaining、ping-pong、ring】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）DMA；TRIGGER_SELF/ENDLESS 模式 RP2040 沒有。
- `channel_config_set_chain_to(&c, other)`：完成後觸發 other；設成自己=不 chain。兩通道都先 claim。
Ping-pong（A↔B 互 chain）：
```c
for (int i = 0; i < 2; i++) {
    dma_channel_config c = dma_channel_get_default_config(chs[i]);
    channel_config_set_transfer_data_size(&c, DMA_SIZE_32);
    channel_config_set_read_increment(&c, false);
    channel_config_set_write_increment(&c, true);
    channel_config_set_dreq(&c, pio_get_dreq(pio, sm, false));
    channel_config_set_chain_to(&c, chs[i ^ 1]);           // A→B、B→A
    dma_channel_configure(chs[i], &c, buf[i], &pio->rxf[sm], N, false);
}
```
接著開兩通道的 IRQ0、裝 DMA_IRQ_0 handler、`dma_channel_start(ch_a)`。ISR：ack 後 `dma_channel_set_write_addr(ch_a, buf[0], false)`（重設不觸發），B 同理；須在另一 buffer 填滿前處理完。兩通道同 DREQ 是否違規 ⚠️未驗證，出錯改 ring。

ENDLESS：`dma_encode_endless_transfer_count()`，只能 abort 停。ISR 快速重啟：`dma_channel_set_read_addr(ch, p, true)`。

【參考卡｜RP2350 DMA 6/8｜完成中斷（IRQ）】

## L02-08

【參考卡｜RP2350 DMA 8/8｜效能：何時不會更快、優化、CRC】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：整顆 DMA 每 clk_sys 最多 1 讀 + 1 寫（≤32 bit），多通道 round-robin 平分 → 一份 memcpy 拆多通道**不會更快**。150 MHz 理論上限約 600 MB/s。
不會比較快：
- 很短的傳輸（數十 bytes 等級，門檻 ⚠️需實測）：設定成本 > memcpy。
- 啟動後立刻 wait：應先讓 CPU 做不碰 dst 的工作，最後才 wait。
- `DMA_SIZE_8` 搬大量：頻寬只用 1/4 → 對齊後用 32-bit，頭尾零碎 bytes 給 CPU。
- CPU 與 DMA 搶同一 SRAM bank → 分開放（SRAM0–3 起 0x20000000、SRAM4–7 起 0x20040000、SRAM8/9 各 4 KB）。
- 讀 flash（XIP）/ APB 週邊：受 QSPI / APB 速度限制。
- 受週邊 DREQ 節流：好處是 CPU 空出來，不是更快。
- 需逐筆運算：DMA 只能搬、bswap、算 CRC/sum。
優化：重疊運算、ping-pong、control block + IRQ_QUIET 減中斷、ISR 只寫一個 trigger alias 重啟、config 算一次重用、`channel_config_set_bswap` 做位元組序。
量測：`time_us_64()` 包住 CPU 版與 DMA 版，各重複 100 次比較。
CRC32：config 也要 `channel_config_set_sniff_enable(&c, true)`（configure 會覆寫 CTRL）；`dma_sniffer_set_data_accumulator(0xFFFFFFFFu)`、`dma_sniffer_set_output_reverse_enabled(true)`、`dma_sniffer_enable(ch, DMA_SNIFF_CTRL_CALC_VALUE_CRC32R, true)`、DMA_SIZE_8，完成後 `dma_sniffer_get_data_accumulator() ^ 0xFFFFFFFFu`（同片段卡 PICO-SNIFF 1）。驗證 "123456789" → 0xCBF43926（沒上板測過）。

【參考卡｜RP2350 PIO 2/8｜9 條指令】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350 PIO = version 1（RP2040 為 v0）。9 條：JMP WAIT IN OUT PUSH PULL MOV IRQ SET；`nop` = `mov y, y`。
| 指令 | 重點 |
|---|---|
| `jmp (cond) L` | cond：無 `!x` `x--` `!y` `y--` `x!=y` `pin` `!osre`。`x--`：X≠0 則跳，先判斷再減（一定減）。L 絕對位址，SDK 自動加 offset |
| `wait pol gpio/pin/irq n` | gpio=絕對號；pin=IN_BASE+n；`wait 1 irq` 成立後自動清 flag |
| `in src, n` | src：pins x y null isr osr；取 src 最低 n bit 移入 ISR |
| `out dst, n` | dst：pins x y null pindirs pc isr exec；從 OSR 移出 n bit |
| `push (iffull) (block\|noblock)` | ISR→RX FIFO，ISR 清 0；預設 block |
| `pull (ifempty) (block\|noblock)` | TX FIFO→OSR；預設 block；noblock 遇空 = `mov osr, x` |
| `mov dst, (op) src` | op：`!`/`~` 反相、`::` 位元反轉；src 含 status |
| `irq (set\|wait\|clear) n (rel)` | flag 0–7；wait=設後等清；rel=加 SM 號 |
| `set dst, v` | dst：pins x y pindirs；v=0–31 |
- n=1–32。大常數用 `pull`+`out y, 32`。
- 不開 autopull 時 `out` 不會等 TX 資料（移出殘值/0）；autopull 開時 `mov` 讀 OSR 未定義 ⚠️未查證。
- Stall：wait 未成立、pull 遇 TX 空、push 遇 RX 滿、irq wait。
- v1 新增（SDK 對 RP2350 自動 `-v 1`；手動 pioasm 加 `.pio_version 1`）：`mov pindirs`、`mov rxfifo[i]`（↔ isr/osr）、`irq prev/next`（不配 rel）、`wait jmppin`。
- 編碼：`out x, 32`=0x6020、`in x, 32`=0x4020、`push`=0x8020。

【參考卡｜RP2350 PIO 5/8｜blink 範例追蹤與 SM 資源】

## L03-06

【參考卡｜RP2350 PIO 6/8｜時序計算與 clkdiv】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：預設 clk_sys 150 MHz（RP2040 為 125 MHz）。不要假設，用 `clock_get_hz(clk_sys)`。
- `f_sm = f_sys / div`，`div = INT + FRAC/256`，1 ≤ div ≤ 65536。
- 一條指令 = 1 + delay 個 SM cycle（不含 stall）。
- `jmp x-- L` 迴圈：X 初值 n → 迴圈體執行 n+1 次。
- `div = f_sys / (bit_rate × cycles_per_bit)`。
- 設計法：先決定每 bit 幾 cycle，每條路徑用 delay 補平，再用 clkdiv 對準速率。
- 小數 div：一階 delta-sigma，部分週期 n、部分 n+1 個 sysclk → 平均對但有 jitter（最多 1 sysclk）。能整數就整數。
- 輸入同步器 2 cycle 延遲。
速查（150 MHz）：
| 目標 | cycles/bit | div |
|---|---|---|
| 最大方波 | 2/週期 | 1 → 75 MHz |
| UART 115200（uart_tx） | 8 | 162.76 |
| UART 1 Mbaud | 8 | 18.75 |
| 10 MHz SM clock | — | 15（整數） |
| 最慢 | — | 65536 → 約 2289 Hz |
uart_tx（`.side_set 1 opt`，delay 上限 7）：
```
    pull       side 1 [7]  ; 停止位 / 閒置高電位
    set x, 7   side 0 [7]  ; 起始位 8 cycle，bit 計數 7
bitloop:
    out pins, 1            ; LSB 先 → out shift 右移
    jmp x-- bitloop [6]    ; 1 + 6 + out 1 = 8 cycle/bit
```
init：out shift 右移、**不** autopull（有明確 pull）、OUT 與 side-set 同一腳、`PIO_FIFO_JOIN_TX`；先 `pio_sm_set_pins_with_mask` 設高再設方向，避免假起始位。

## L03-07

【參考卡｜RP2350 PIO 7/8｜DMA 餵 PIO、優化】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：16 DMA ch、3 個 PIO；DREQ 號與 RP2040 不同，用 `pio_get_dreq()`。
```c
int ch = dma_claim_unused_channel(true);
dma_channel_config dc = dma_channel_get_default_config(ch);
channel_config_set_transfer_data_size(&dc, DMA_SIZE_32);
channel_config_set_read_increment(&dc, true);    // 來源陣列往前走
channel_config_set_write_increment(&dc, false);  // 目的地固定是 FIFO
channel_config_set_dreq(&dc, pio_get_dreq(pio, sm, true));
dma_channel_configure(ch, &dc,
                      &pio->txf[sm],   // write_addr（先目的地）
                      src,             // read_addr
                      N,               // 筆數，不是 byte 數！
                      true);
dma_channel_wait_for_finish_blocking(ch);
```
- RX：read_increment=false、write_increment=true、dreq=`pio_get_dreq(pio, sm, false)`、read_addr=`&pio->rxf[sm]`。
- 雙向：**先啟動 RX channel 再 TX**。DMA 跑時 CPU 不可 put/get 同一 FIFO。
優化：
- `.wrap` 取代尾端 `jmp`（每圈少 1 cycle）；autopull/autopush 省 pull/push。
- 時脈/控制線放 side-set；單向用 `PIO_FIFO_JOIN_TX/RX`。
- 位元打包：`in pins, 8` + autopush 32 → 每 word 4 樣本。
- 同程式載入一次、多 SM 跑不同腳；整數 clkdiv 無 jitter。
- 單純位元運算 CPU 可能更快（M33 有 `RBIT`、SDK `__rev()`）；PIO 價值在與 I/O 同步、與 CPU 並行。

SIO/PIO 輸入永遠連著；DMA 不能存取 SIO（GPIO）。

## L04-03

【參考卡｜RP2350 週邊 3/8｜SPI】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：2 個 SPI（PL022），TX/RX FIFO 各 8，4–16 bit frame，**只支援 MSB first**。SSPCLK = clk_peri。master 最高 clk_peri/2（公式 75 MHz；datasheet 文字寫 70.5 Mb/s，不一致 ⚠️，以 `spi_init` 回傳值為準）；slave 最多 clk_peri/12。

```c
spi_set_format(spi0, 8, SPI_CPOL_0, SPI_CPHA_0, SPI_MSB_FIRST);
```

- 症狀：全 FF/00 → MISO 沒設 SPI 功能、CS 沒拉低、mode 錯；最後 byte 被截 → DMA TX 完就拉 CS。

【參考卡｜RP2350 週邊 4/8｜I2C】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350（Pico 2）：2 個 I2C（DW_apb_i2c），FIFO 16，100k / 400k / 1 Mbit/s（無 3.4M High-speed）。時脈 = **clk_sys**（不是 clk_peri）。**需要 pull-up**（外部 4.7 kΩ 佳，內建只適合短線）。
```c
i2c_init(i2c0, 400 * 1000);
gpio_set_function(4, GPIO_FUNC_I2C);    // SDA
gpio_set_function(5, GPIO_FUNC_I2C);    // SCL
gpio_pull_up(4); gpio_pull_up(5);
// 讀暫存器：寫 reg（nostop=true，送 repeated START）→ 讀 n
int r = i2c_write_timeout_us(i2c0, addr, &reg, 1, true, 2000);
if (r == 1) r = i2c_read_timeout_us(i2c0, addr, buf, n, false, 2000 + 100 * n);
```
- 簽名：`int i2c_write_timeout_us(i2c, addr, src, len, nostop, timeout_us)`，read 同型。
- `addr` 是 **7-bit**（例如 0x68），不要傳左移過的 8-bit（0xD0）。
- 回傳：成功 = byte 數；位址沒 ACK = `PICO_ERROR_GENERIC`；逾時 = `PICO_ERROR_TIMEOUT`；寫入時資料被 NAK = 已成功 byte 數（< len）。一律檢查 `r < 0` 或 `r != len`，用名稱比較。
- 非 timeout 版（`i2c_write_blocking`）在沒 pull-up / SCL 被拉住時可能永遠卡住 → 考試用 `_timeout_us`。
- 寫暫存器：reg 與資料放同一 buffer 一次送，不要拆兩次 write。
- Bus scan：每個位址讀 1 byte 看回傳 ≥ 0；跳過保留位址 0x00–0x07、0x78–0x7F。
- 症狀：卡住 → 沒 pull-up；GENERIC → 位址錯/接反/沒電；讀值錯 → 寫 reg 時 nostop 用了 false。
- 每 byte = 9 個 SCL 週期；400 kHz 約 44 kB/s。優化：burst 讀連續暫存器。

## L04-05

【參考卡｜RP2350 週邊 5/8｜PWM】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350：12 slice（RP2040 8）× A/B 兩輸出；Pico 2（QFN-60）GPIO 0–29 只接 slice 0–7，slice 8–11 沒腳但可當週期中斷 timer。計數時脈 = clk_sys（預設 150 MHz）。同 slice 的 A/B **共用頻率**（TOP、分頻），duty 各自。
公式：
- `f_PWM = f_sys / ((TOP + 1) × (PH_CORRECT + 1) × DIV)`，`DIV = INT + FRAC/16`，1 ≤ DIV < 256
- duty = CC / (TOP + 1)；CC=0 → 0%、CC=TOP+1 → 100%；counter < CC 時輸出高
- **要 N 個 count 的週期：`pwm_set_wrap(slice, N - 1)`**
150 MHz 速查：20 kHz → DIV 1、TOP 7499；1 kHz → DIV 2.5（INT 2, FRAC 8）、TOP 59999；50 Hz → DIV 64、TOP 46874（1.5 ms ≈ CC 3516）。
設定順序（1 kHz 例）：`slice = pwm_gpio_to_slice_num(gpio)` → `gpio_set_function(gpio, GPIO_FUNC_PWM)` → `pwm_set_clkdiv_int_frac4(slice, 2, 8)` → `pwm_set_wrap(slice, 59999)` → `pwm_set_gpio_level(gpio, level)`（25% = (TOP+1)/4）→ `pwm_set_enabled(slice, true)`。
- `pwm_set_clkdiv(float)` 小數捨去到 1/16；精確用 `int_frac4`。
- `pwm_set_mask_enabled(mask)` 直接寫 EN：沒列在 mask 的 slice 會被關掉。
- CC、TOP 雙緩衝，下次 wrap 生效。
- Wrap IRQ：`pwm_set_irq_enabled(slice, true)` + handler 裝在 `PWM_DEFAULT_IRQ_NUM()`；handler 先 `pwm_clear_irq(slice)`。
- DMA 寫 `&pwm_hw->slice[s].cc` 必須 32-bit（低 16=A、高 16=B）；16-bit 寫會被複製成 A=B。
- B 腳可當輸入：`PWM_DIV_B_RISING` 量頻率、`PWM_DIV_B_HIGH` 量 duty。

## L04-08

【參考卡｜RP2350 週邊 8/8｜中斷（IRQ）規則與號碼】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
RP2350：52 個外部 IRQ（RP2040 32），優先權 8-bit 只有**高 4 bit 有效**（16 級；RP2040 高 2 bit）。Hazard3 IRQ 延遲較長 ⚠️未量測；SDK API 相同。
IRQ 號（用名稱，不寫數字）：TIMER0_IRQ_0..3=0–3、TIMER1=4–7、PWM_IRQ_WRAP_0/1=8/9、DMA_IRQ_0..3=10–13、USBCTRL=14、PIO0/1/2_IRQ_0/1=15–20、IO_IRQ_BANK0=21、SIO_IRQ_FIFO=25、SIO_IRQ_BELL=26、SPI0/1=31/32、UART0/1=33/34、ADC_IRQ_FIFO=35、I2C0/1=36/37、SPARE_IRQ_0..5=46–51。
API：
- `irq_set_exclusive_handler(num, h)`（已有 handler 會 assert）、`irq_add_shared_handler(num, h, order_priority)`、`irq_set_enabled(num, true)`、`irq_set_priority(num, p)`（0x00 最高、預設 0x80、0xff 最低）、`irq_set_pending(num)`。
- shared 的 `order_priority`：**數字大的先被呼叫**（與 `irq_set_priority` 相反）；全部 shared handler 合計上限預設 4（`PICO_MAX_SHARED_IRQ_HANDLERS`）。
- `irq_set_enabled` 只影響**呼叫的那顆核**。UART、SPI、DMA、PWM、TIMER 等只在一顆核 enable。
- GPIO IRQ 是 per-core，每核一個 callback。
ISR 規則：
1. 先清週邊旗標（PWM 寫 INTR、GPIO acknowledge、UART 讀空 FIFO、DMA 寫 INTS），否則一直重進。
2. 短：搬資料、設旗標、推 ring。
3. 不要 printf、sleep、malloc。
4. 時間關鍵 ISR 用 `__not_in_flash_func(name)` 放 RAM。
5. 共享變數 volatile；多欄位更新用 `save_and_disable_interrupts()` / `restore_interrupts()`。
6. 重活丟 bottom half：`user_irq_claim_unused` + 低優先權 + `irq_set_pending`。

## L05-01

【參考卡｜多核同步 1/8｜臨界區原則與「各自累加再合併」】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
適用：Linux pthread 與 RP2350（Pico 2）雙核 pico-sdk。
原則：
- `counter++` = 讀 → 加 → 寫三步，兩個執行緒 / 兩顆核同時做會掉更新（結果偏少、每次不同；單核可能剛好對）
- `volatile` 不是同步：不保證原子、不保證跨執行緒順序；只讓 race 更容易出現
- C11：兩執行緒存取同一非 atomic 物件、至少一方寫、沒有 happens-before → data race = UB
- 臨界區越短越好：計算、I/O、printf、malloc 移到鎖外；鎖內只做讀 / 寫；鎖內不呼叫會阻塞的函式
- 最快是不共享：每執行緒 / 每核累加區域變數，最後合併一次
- 單一整數 → atomic；多欄位一起改 → 鎖
- 執行緒數 > CPU 數（`nproc`）時 spinlock 空轉 → 改 mutex
- Linux false sharing：各執行緒寫的變數 `alignas(64)` 分開（RP2350 無 data cache，沒有這問題）
正解範例（demo counter，連 sink 的 race 一起修）：
```c
static atomic_long counter;
static void *worker_partitioned(void *arg) {
    (void)arg;
    long local = 0;
    uint32_t local_sink = 0;
    for (int i = 0; i < ROUNDS; i++) {
        local_sink += work(i);
        local++;
    }
    atomic_fetch_add_explicit(&counter, local, memory_order_relaxed);
    return (void *)(uintptr_t)local_sink;
}
```
- main 在 `pthread_join` 之後讀 counter（join 建立 happens-before，relaxed 就夠）
- 同步次數從 N×ROUNDS 降到 N 次
- demo 的 `sink += work(i)` 沒鎖也是 race

【參考卡｜多核同步 2/8｜POSIX pthread API 與工具（Linux）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。

```c
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
```

```c
pthread_mutex_lock(&m);

```

工具：
- 編譯加 `-pthread`

- `valgrind --tool=helgrind`

- `time`：user 很高但 real 沒降 → spinlock 空轉

## L05-03

【參考卡｜多核同步 3/8｜C11 atomics 與 memory order】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
適用：Linux 與 RP2350（Pico 2）。
```c
#include <stdatomic.h>
atomic_long counter = 0;
atomic_fetch_add(&counter, 1);         // 回傳舊值，預設 seq_cst
atomic_fetch_add_explicit(&counter, 1, memory_order_relaxed);
long v = atomic_load_explicit(&counter, memory_order_acquire);
atomic_store_explicit(&flag, 1, memory_order_release);
long expected = atomic_load(&x);
while (!atomic_compare_exchange_weak(&x, &expected, expected * 2)) { }
```
- compare_exchange_weak 可能偽失敗 → 放迴圈；失敗時 expected 被更新成目前值
- atomic_flag 是唯一保證 lock-free 的型別
memory order：
- relaxed：只保證本身原子；用於計數（join 後才讀）
- acquire（load）：之後的讀寫不會移到前面
- release（store）：之前的讀寫不會移到後面
- seq_cst（預設）：不確定時用
- 發布資料：寫資料 → release store 旗標；讀方 acquire load 讀到旗標後看得到資料
限制：
- 很多執行緒狂打同一 atomic 仍慢 → 各自累加再合併
- 兩個 atomic 各自原子，合起來不是原子 → 要一起改用鎖
RP2350：
- 1/2/4 byte 對齊的 atomic 是 lock-free（Arm ldrex/strex、RISC-V lr/sc/amo）；64-bit 由 pico_atomic 用 spinlock 保護
- RP2040 全部用 spinlock 模擬
- 跨核 exclusive 靠 global monitor，只涵蓋 SRAM（不含 XIP/PSRAM）→ atomic 變數放 SRAM；reservation granule 16 bytes ⚠️未查證
- 兩核對同一 16-byte 區塊內不同變數做 atomic 會互相干擾 ⚠️未驗證（推論）

## L05-04

【參考卡｜多核同步 4/8｜pico 多核 API：launch、FIFO、queue_t】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2），非 RP2040。CMake `target_link_libraries(app pico_stdlib pico_multicore)`；`#include "pico/multicore.h"`、`"pico/util/queue.h"`。
啟動 core1：
- `multicore_launch_core1(void (*entry)(void))`；`multicore_reset_core1()`（只能 core0 呼叫）
- launch 內部用 FIFO 握手 → launch 前不要在 FIFO 放自己的資料
- core1 stack 預設 2 kB（`PICO_CORE1_STACK_SIZE`）在 SCRATCH_X（4 kB）→ 大陣列改 static，或調大 stack
- core1 entry 寫成 `while (1)` 不返回；`get_core_num()` 回 0 或 1
FIFO：
- RP2350 每方向只有 4 格 × 32 bit（RP2040 是 8 格）
- `multicore_fifo_push_blocking(u32)`、`multicore_fifo_pop_blocking()`、`_rvalid()`、`_wready()`、`_drain()`、`_push_timeout_us`、`_pop_timeout_us`
- 滿了還寫 → 丟棄並設 WOF；空了還讀 → 無效值並設 ROE
- 只傳指標或索引；SDK 建議資料傳遞優先用 queue_t（FIFO 被 launch、lockout 佔用）
- 兩核 FIFO IRQ 共用 `SIO_IRQ_FIFO`
queue_t（跨核 + IRQ 安全）：
```c
queue_init(&q, sizeof(job_t), 4);
queue_add_blocking(&q, &j);
queue_remove_blocking(&q, &j);
queue_try_add(&q, &j);      // 滿 → false
queue_try_remove(&q, &j);   // 空 → false
```
- 元素 memcpy 複製；`queue_init` 回傳 void，內部 calloc 不檢查失敗
- ISR 中只用 `queue_try_*`
- queue 先初始化，再 launch core1
- 傳 buffer 指標時，交出後到拿回前生產者不能再碰（所有權轉移）

## L05-05

【參考卡｜多核同步 5/8｜pico 鎖：critical_section、mutex、sem、spinlock、E2】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2）pico-sdk，`#include "pico/sync.h"`、`"hardware/sync.h"`。
- `critical_section_init(&cs)` / `_enter_blocking` / `_exit`：關本核 IRQ + spinlock → 跨核 + ISR 都安全；極短；不可重入（巢狀要 `critical_section_init_with_lock_num` 給不同編號）
- `mutex_init` / `mutex_enter_blocking` / `mutex_exit` / `mutex_try_enter(&m, NULL)`：可持有較久；同核再 enter 會 deadlock（用 recursive_mutex_t）；ISR 不可阻塞，只能 try
- `sem_init(&s, init, max)`、`sem_acquire_blocking`、`sem_release`（ISR 可呼叫）；名稱不同於 POSIX
- spinlock：
```c
lk = spin_lock_init(spin_lock_claim_unused(true));
uint32_t save = spin_lock_blocking(lk);
shared_x++;
spin_unlock(lk, save);
```
  只能持有很短；持有時不拿別的 spinlock；不可重入
- `save_and_disable_interrupts()` / `restore_interrupts(s)` 只擋本核
- `multicore_lockout_*` 不是資料鎖（寫 flash 用）
RP2350-E2 erratum：
- 寫 SIO 0x180–0x1FC 會誤釋放低 0x80 的硬體 spinlock（A2 有；A4 公告未列為已修）
- SDK 預設 `PICO_USE_SW_SPIN_LOCKS`（RAM 中軟體 spinlock），API 不變
- 不要直接寫 `sio_hw->spinlock[]`（RP2040 舊寫法）；編號用 `PICO_SPINLOCK_ID_*`
選哪個：
- 單一 32-bit 計數 / 旗標跨核 → C11 atomic
- 幾個欄位一起改、ISR 或另一核會碰 → critical_section_t
- 持有較久、只有兩核主程式碰 → mutex_t
- 通知 → semaphore_t；傳資料 → queue_t；只有同核 ISR 與主迴圈 → 關中斷

## L05-06

【參考卡｜多核同步 6/8｜ISR 與主迴圈共享變數】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2）pico-sdk 裸機。
```c
static volatile bool data_ready;
static volatile uint32_t sample;
void my_isr(void) {
    sample = read_hw();
    data_ready = true;
}
int main(void) {
    while (true) {
        if (data_ready) {
            uint32_t save = save_and_disable_interrupts();
            uint32_t s = sample;
            data_ready = false;
            restore_interrupts(save);
            handle(s);
        }
    }
}
```
規則：
- 同核 ISR ↔ 主迴圈：單一對齊 32-bit 旗標用 volatile 是嵌入式慣例（C 標準正式只保證 volatile sig_atomic_t）
- 多欄位或 RMW（`count++`）→ 主程式那側關中斷，或用 atomic
- 64-bit 變數在 32-bit 核心上讀寫不是一條指令 → 會讀到一半新一半舊，一定要保護
- ISR 與另一核共享 → 只關中斷不夠，用 critical_section_t、atomic 或 queue_t
- 關中斷時間越短越好（會延誤 timer、USB、UART）；處理放在關中斷區外
- ISR 內不要 printf、不要阻塞（不呼叫 mutex_enter_blocking、queue_add_blocking）、不要拿主程式可能長時間持有的鎖 → 會直接 deadlock
- ISR 中用 `_try_` 版本（queue_try_add、mutex_try_enter）；sem_release 可在 ISR
- stdout 有 mutex：兩核 printf 不會撕裂但順序不定；熱迴圈與臨界區內不要 printf

## L05-07

【參考卡｜多核同步 7/8｜RP2350 雙核分工、SRAM bank、DMA】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2），2 核，最多 2 倍加速。
資料分割（每核一半，各自累加，最後合併）：
```c
static void core1_main(void) {
    core1_result = sum_range(N / 2, N);
    __dmb();
    multicore_fifo_push_blocking(1);
    while (true) __wfi();
}
// core0：
multicore_launch_core1(core1_main);
int64_t s0 = sum_range(0, N / 2);
(void)multicore_fifo_pop_blocking();
__dmb();
int64_t total = s0 + core1_result;
```
- FIFO 本身不是 C 層級 barrier → push 前、pop 後各 `__dmb()`；或結果放 queue_t
- launch 握手也算時間；重複使用時 core1 常駐、用 queue 派工
- pipeline：吞吐量取決於最慢階段
SRAM：
- 0x20000000 起 256 kB 交錯 SRAM0–3、0x20040000 起 256 kB 交錯 SRAM4–7（每 4 bytes 換 bank）
- SRAM8 0x20080000 = SCRATCH_X（core1 stack）、SRAM9 0x20081000 = SCRATCH_Y（core0 stack），各 4 kB
- 不同 bank 可同週期並行；兩核 / DMA 搶同 bank 才互等
- 單核熱資料 `__scratch_x("name")`；熱函式 `__not_in_flash_func(f)`
DMA（RP2350 16 channel）：
- `dma_claim_unused_channel(true)` → `dma_channel_get_default_config(ch)` → `channel_config_set_write_increment(&c, true)`（預設 write 不遞增！）→ `dma_channel_configure(ch, &c, dst, src, dma_encode_transfer_count(N), true)`（N 是筆數不是 bytes；SDK < 2.2 沒有這函式 → 直接填 N）→ 做別的事 → `dma_channel_wait_for_finish_blocking(ch)` 後才讀 dst

以下是正確的參考資料，若與你的記憶不同，以這張為準。

- 大於 8 bytes 的 struct 以參考傳遞
- sp 進入函式時 16-byte 對齊
- `.S` 函式可隨意用 a0–a7、t0–t6；要用 s0–s11 或呼叫其他函式（會覆蓋 ra）必須先存堆疊、離開前還原

## L06-02

【參考卡｜RISC-V Hazard3 2/8｜RV32I 指令、立即值、pseudo】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2）Hazard3，RV32。
立即值範圍：
- I/S 型 12-bit 有號：-2048～2047；移位 shamt 0～31
- B（條件分支）±4 KiB；J（jal）±1 MiB；lui/auipc 20-bit（左移 12）
- 32 位元常數：addi 的 imm 會正負號擴展，低 12 位 ≥0x800 時 lui 要 +1。`hi=(x+0x800)>>12`，`lo=x-(hi<<12)`
  例：li a0,0x12345fff → `lui a0,0x12346` + `addi a0,a0,-1`
- 沒有 subi（用負 imm）；`andi a0,a0,-16` = 清低 4 位
- sll/srl/sra 只取 rs2[4:0]（移位量 mod 32）
Load/Store：lb/lh 正負號擴展，lbu/lhu 零擴展；lh 需 2-byte、lw 需 4-byte 對齊；無 lwu/ld
無旗標暫存器，64 位元加法（a1:a0）+（a3:a2）：
```asm
add  a0, a0, a2
sltu t0, a0, a2
add  a1, a1, a3
add  a1, a1, t0
```
pseudo：
- mv=addi rd,rs,0；not=xori -1；neg=sub rd,x0,rs
- seqz=sltiu rd,rs,1；snez=sltu rd,x0,rs
- j=jal x0；jr=jalr x0,0(rs)；ret=jalr x0,0(ra)
- call=auipc ra+jalr ra；tail=auipc t1+jalr x0
- bgt/ble/bgtu/bleu a,b → blt/bge/bltu/bgeu b,a（交換運算元）
- S 型 `sw rs2, imm(rs1)`：rs2 是要存的值、rs1 是位址；B 型 `blt rs1, rs2, L` = if (rs1 < rs2) goto L。分支用來「跳過」下面幾行時，C 的 if 條件和分支條件相反（blt 跳過 ↔ if (rs1 >= rs2)）。
- zext.b=andi 255；csrr=csrrs rd,csr,x0
M 擴充：除以 0 不 trap（div/divu 回傳全 1，rem 回傳被除數）；INT_MIN/-1 回傳 INT_MIN、餘 0（C 層級仍 UB）
fence 在 Hazard3 是 no-op ⚠️未查證；寫程式碼到 RAM 後要 fence.i

## L06-06

【參考卡｜RISC-V Hazard3 6/8｜cycle 計數（mcycle）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2）Hazard3。
- `mcountinhibit` 重置值 0x5（bit0 CY、bit2 IR 為 1 = 停止）。pico-sdk 不會幫你清 → 不清就永遠讀到 0 或不變
- 開啟：`csrci mcountinhibit, 5`（mcycle + minstret 都開），或 `csrci mcountinhibit, 1`（只開 cycle）
- 沒有 `time` CSR（讀了 illegal instruction，mcause 2）；改用 `time_us_32()`
- Debug mode 中計數器不跑，單步除錯量不到真實 cycle
```c
static inline void cycles_enable(void) {
    asm volatile ("csrci mcountinhibit, 5");
}
static inline uint32_t mcycle32(void) {
    uint32_t c;
    asm volatile ("csrr %0, mcycle" : "=r"(c));
    return c;
}
```
pico-sdk 版：
```c
#include "hardware/riscv.h"
riscv_clear_csr(mcountinhibit, 5);
uint32_t t0 = riscv_read_csr(mcycle);
```
量測步驟：
1. 先量空測開銷：t0、t1 連讀，overhead = t1 - t0
2. cycles = (t1 - t0) - overhead（無號相減自動處理回繞）
3. 結果要被使用（印出 / 存 volatile），否則可能被優化掉
4. 多跑幾次取最小值或中位數；第一次常因 XIP cache miss 偏慢
- 64 位元：讀 mcycleh → mcycle → mcycleh，兩次 hi 不同就重試
- 150 MHz 下 32 位元 mcycle 約 28.6 秒回繞

【參考卡｜RISC-V Hazard3 7/8｜inline asm 與 .S 函式】

## L06-08

【參考卡｜RISC-V Hazard3 8/8｜C 位元技巧與 UB 陷阱】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2）Hazard3。一律用 uint32_t、常數加 u。
技巧：
- 2 的冪：`x && !(x & (x - 1))`
- 最低位 1：`x & -x`；清最低位 1：`x & (x - 1)`
- 取欄位（w<32）：`(x >> l) & ((1u << w) - 1)`
- 寫欄位：`m = mask << l; (x & ~m) | ((v << l) & m)`（v 要先 mask）
- w 位正負號擴展：`m = 1u << (w-1); (int32_t)((v ^ m) - m)`
- 無分支選擇（c 為 0/1）：`b ^ ((a ^ b) & -(uint32_t)c)`
- 對齊向上：`(x + a - 1) & ~(a - 1)`
- 有 0 byte：`((x - 0x01010101u) & ~x & 0x80808080u) != 0`
- 例 x=0xA5：x\|(1u<<1)=0xA7、x&~1u=0xA4、(x>>4)&0xF=0xA
UB / 陷阱：
- 移位 ≥32 或負數 UB（硬體 sll 只取低 5 位）；`1 << 31`（int）UB → `1u << 31`
- 有號溢位 UB → 用 uint32_t 運算
- __builtin_clz(0)/ctz(0) UB（硬體回 32）
- 整數提升：`~(uint8_t)a` 變 int；`b << 24`（uint8_t b）要寫 `(uint32_t)b << 24`；`(uint32_t)x * x`
- `x & 0xF == 0` 等於 `x & (0xF == 0)` → 加括號
- 有號負數 `x/4` ≠ `x>>2`
- MMIO 用 volatile（不保證原子）
- 非對齊指標轉型 `*(uint32_t *)(buf + 1)` 會 trap → memcpy
- RISC-V psABI 的 char 為無號
最佳化：先 mcycle 量、熱點放 SRAM、load 與使用間插無關指令、展開＋多累加器、用結束指標比較、迴圈內避 div/rem 與 float；測試邊界 0、0xFFFFFFFF、0x80000000、n=0/1

以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2）Cortex-M33。前提：單核、無 XIP cache miss、無 DMA。⚠️未逐條對照 datasheet 原文，以 cycle 計數實測為準。「延遲」= 下一條用到結果就 +1。
- 一般 ALU 1，無延遲
- Operand2 移位非 LSL #0～3（如 LSL #4、LSR、ASR、ROR），或立即值需移位：1 + 延遲；這類加 S 一定 +1
- UBFX/SBFX/BFI、獨立 LSL/LSR/ASR/ROR、MOVW、ADDW/SUBW：1，無延遲
- SEL：有延遲
- LDR：1 / 暫存器，有延遲（LDM/POP 只有最後一個暫存器有）；STR 1
- 位址暫存器也算來源：`ldr r0,[r0]` 後立刻 `ldr r1,[r0]` 一定 +1
- MUL/MLA/UMULL/SMULL：1 + 延遲；連續 MAC 累加同一暫存器（對）無懲罰
- SDIV/UDIV：n = 兩數最高位 1 的位置差；n<0 → 2，否則 4+⌊n/4⌋（最多約 11）。例 1000/10 → 5
分支：
- taken = 2 + L + U − (K&F)；not-taken = 1 − F
- L=1：分支來自 load（POP {pc}、LDR pc）
- U=1：目標未 word 對齊且為 32-bit 指令
- F=1：可 fold（B、B<cond>、BX LR，且前一條是 16-bit）
- K=0：條件分支且前一條設旗標；其他情況 K=1
- 技巧：cmp/subs 與 bne 間塞一條無關 16-bit 指令 → taken 1 cycle，那條免費
- 無分支預測項；迴圈頂 `.p2align 2`
其他：IT 中條件不成立的指令仍 1 cycle；16-bit nop 可 fold（0 cycle）→ 要耗 1 cycle 用 `nop.w`（`__nop()`）
- 從 SRAM 執行時 literal 在 PC+8（mod 16）附近可能 +1；flash（0x10000000 起）miss 慢很多 → 熱點放 SRAM

【參考卡｜Cortex-M33 6/8｜cycle 計數（DWT CYCCNT）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。

```c
#include "hardware/structs/m33.h"
static inline void cyc_init(void) {
    m33_hw->demcr     |= M33_DEMCR_TRCENA_BITS;
    m33_hw->dwt_cyccnt = 0;
    m33_hw->dwt_ctrl  |= M33_DWT_CTRL_CYCCNTENA_BITS;
}
static inline uint32_t cyc_now(void) { return m33_hw->dwt_cyccnt; }
```
- 位址：DEMCR 0xE000EDFC、DWT_CTRL 0xE0001000、DWT_CYCCNT 0xE0001004
- CMSIS 寫法：`DCB->DEMCR |= DCB_DEMCR_TRCENA_Msk; DWT->CYCCNT = 0; DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;`
- 每顆核心各有 DWT：在 core1 量要在 core1 上 cyc_init()
- 150 MHz 約 28.6 秒回繞；無號相減 t1 - t0 處理一次回繞
- 一直是 0：沒設 TRCENA 或 CYCCNTENA、在另一核設的、NOCYCCNT=1
量測步驟：
```c
cyc_init();
uint32_t t0 = cyc_now(), t1 = cyc_now();
uint32_t overhead = t1 - t0;
t0 = cyc_now();
volatile uint32_t sink = func_under_test(buf, n);
t1 = cyc_now();
uint32_t cycles = (t1 - t0) - overhead;
```
- 多次取最小值或中位數；第一次常有 XIP cache miss
- 排除中斷：`uint32_t s = save_and_disable_interrupts(); … restore_interrupts(s);`
- 替代：SysTick 24 位元向下計數，150 MHz 約 0.11 秒回繞；RTOS 已用 SysTick 時不要動
- µs 等級用 `time_us_32()`

## L08-03

【參考卡｜ROS 2 3/8｜QoS 預設值與相容性】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
環境：ROS 2 Jazzy。
預設 profile：
- default（`create_publisher(T, '/t', 10)` 就是這個）：KEEP_LAST、depth 10、RELIABLE、VOLATILE。
- sensor_data（`from rclpy.qos import qos_profile_sensor_data`）：KEEP_LAST、depth 5、BEST_EFFORT、VOLATILE。
相容規則：publisher 提供的品質 ≥ subscription 要求才相容。
- Reliability：pub BEST_EFFORT + sub RELIABLE → 不相容；其他相容。
- Durability：pub VOLATILE + sub TRANSIENT_LOCAL → 不相容；兩端都 TRANSIENT_LOCAL 才收得到舊訊息。
- Deadline / Lease：sub 有設而 pub 沒設，或 pub x > sub y → 不相容。
- Liveliness：pub AUTOMATIC + sub MANUAL_BY_TOPIC → 不相容。
- History / Depth 不影響相容性。任一 policy 不相容 → 這對完全不傳。
不相容 = 靜默失敗：無例外、topic info 的 pub/sub 數都正確，但收不到。log 只有 WARN：
- pub 端：`New subscription discovered on topic '/x', requesting incompatible QoS. No messages will be sent to it.`
- sub 端：`New publisher discovered on topic '/x', offering incompatible QoS. No messages will be received from it.`
確認：`topic info -v` 逐端比對。
`ros2 topic echo` 會自動配合現有 publisher 的 QoS（啟動時沒 publisher 就用 sensor_data），所以「echo 看得到、我的 node 收不到」常是自己 subscription 太嚴格。重現：`ros2 topic echo /x --qos-reliability reliable` 接 best-effort publisher。
RELIABLE + KEEP_LAST 下 subscriber 太慢，舊訊息仍會被覆蓋而掉；一筆不少需 KEEP_ALL 或夠大 depth。

## L08-04

【參考卡｜ROS 2 4/8｜rclpy 最小 pub/sub/timer 程式】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
環境：ROS 2 Jazzy rclpy 單檔。
```python
import rclpy
from rclpy.node import Node
from rclpy.executors import ExternalShutdownException
from std_msgs.msg import Int32
class Relay(Node):
  def __init__(self):
    super().__init__('relay')
    self.declare_parameter('scale', 2)
    self.scale = self.get_parameter('scale').value
    self.pub = self.create_publisher(Int32, '/double', 10)
    self.sub = self.create_subscription(Int32, '/number', self.on_msg, 10)
    self.timer = self.create_timer(1.0, self.on_timer)
    self.count = 0
  def on_msg(self, msg):
    out = Int32()
    out.data = msg.data * self.scale
    self.pub.publish(out)
    self.count += 1
  def on_timer(self):
    self.get_logger().info(f'relayed {self.count} msgs')
def main():
  rclpy.init()
  node = Relay()
  try:
    rclpy.spin(node)
  except (KeyboardInterrupt, ExternalShutdownException):
    pass
  finally:
    node.destroy_node()
    rclpy.try_shutdown()
if __name__ == '__main__':
  main()
```
- 順序：publisher (type, topic, qos)；subscription (type, topic, callback, qos)。qos=10 即 KEEP_LAST 10、RELIABLE、VOLATILE。
- 沒 spin 則 callback 不跑；timer 週期單位是秒。

## L08-05

【參考卡｜ROS 2 5/8｜Jazzy 特有陷阱】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
環境：ROS 2 Jazzy（ros2cli / rclpy jazzy 分支原始碼確認）。
1. `ros2 topic pub --once`（或 `-t N`）預設 `-w/--wait-matching-subscriptions` = 1：等到 1 個「相容」subscription 才發。沒 subscriber 或 QoS 不相容 → 一直卡著像當掉。強制發：`-w 0`，或 `--max-wait-time-secs 3`。不加 --once/-t 時 -w 預設 0、每秒發一次。
2. rclpy 訊息欄位預設不檢查範圍（Iron 起關閉）。Int32 的 `data` 給超出 int32 的值不丟例外，在 C 層轉型時靜默變錯值（取低 32 位 = 二補數回繞；實測 2**31+5 → -2147483643）。Python int 本身不溢位，要依規格自己決定截斷 / 夾限 / 回繞。設 `ROS_PYTHON_CHECK_FIELDS=1`（或建構時 `check_fields=True`）才會 assert；此時 callback 例外會讓 spin 中止、node 消失。回繞：`((v + 2**31) & 0xFFFFFFFF) - 2**31`。
3. Executor / callback group：node 預設 callback group 是 MutuallyExclusive。只換 MultiThreadedExecutor、callback 都在預設 group → 仍一次一個。要並行：MultiThreadedExecutor 且放不同 group（或 Reentrant）。Python 有 GIL，純運算不會多核加速。
4. callback 內同步 service call（`client.call()`）→ 死結；用 `call_async` + `future.add_done_callback`。
5. `ros2 topic delay` 只能用在有 `header.stamp` 的訊息（Int32 不行）。
6. `ROS_LOCALHOST_ONLY` 已 deprecated（設 1 仍生效但印 WARN），改 `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`（預設 SUBNET）。
7. `ros2 service call` 型別必填；`ros2 action type` 是 Jazzy 新增。
8. rclpy 有 `from rclpy.experimental import EventsExecutor`（7.1.4 起，實驗性）。

## L08-06

【參考卡｜ROS 2 6/8｜Executor 與 callback group】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
環境：ROS 2 Jazzy（rclpy / rclcpp）。
- `rclpy.spin` / `rclcpp::spin` = SingleThreadedExecutor。
- MutuallyExclusive：同組一次一個。Reentrant：同組（含同一 callback 自己）可並行。node 預設 group = MutuallyExclusive。
- 只有 MultiThreadedExecutor + 不同 group（或 Reentrant）才真的並行 → 共享資料加鎖（`threading.Lock` / `std::mutex`），鎖要短。
- rclpy 有 GIL：只讓阻塞型 callback 不互卡，純 Python 運算不加速。
- 死結：callback 內同步呼叫 service，而 response 與呼叫者同 group 或單執行緒 → 永遠等不到。解：`call_async`。
- callback 不可 `time.sleep()` / `while True`；固定頻率用 timer。
```python
from rclpy.callback_groups import MutuallyExclusiveCallbackGroup, ReentrantCallbackGroup
from rclpy.executors import MultiThreadedExecutor
g_timer = MutuallyExclusiveCallbackGroup()
g_sub = MutuallyExclusiveCallbackGroup()
self.create_timer(0.01, self.fast_loop, callback_group=g_timer)
self.create_subscription(Int32, '/number', self.on_msg, 10, callback_group=g_sub)
ex = MultiThreadedExecutor()
ex.add_node(node)
ex.spin()
```
rclcpp：`create_callback_group(rclcpp::CallbackGroupType::MutuallyExclusive)`；subscription 用 `SubscriptionOptions opts; opts.callback_group = g;`；`create_wall_timer(10ms, tcb, g2)` 第三參數是 group。

## L08-07

【參考卡｜ROS 2 7/8｜效能 / 延遲 / 吞吐量優化】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
環境：ROS 2 Jazzy（rclpy / rclcpp）。
先量測再改：`ros2 topic hz`（頻率）、`ros2 topic bw`（頻寬與訊息大小）、`ros2 topic delay`（需 header.stamp）、程式內 `time.perf_counter()` / `std::chrono::steady_clock`。輸入 hz vs 輸出 hz：輸出較低 = 跟不上。
槓桿：
1. callback 不阻塞：移除 sleep、長迴圈、同步 I/O、同步 service call；重活移到另一 thread / group。最常見的頻率下降原因。
2. 高頻路徑不要每筆 `print(..., flush=True)` 或 `get_logger().info`；改計數，timer 每秒印一次。
3. 發布頻率合理；不需要的資料不要發。
4. QoS depth：延遲優先用小 depth（1～5）只留最新；完整性優先用大 depth 或 KEEP_ALL。depth 大 + 消費者慢 = 延遲累積。
5. 高頻感測用 BEST_EFFORT（不重送、延遲穩）；不能掉的用 RELIABLE。不需給晚到者就用 VOLATILE。
6. 訊息小：最小足夠型別（Int32 而非 String 轉數字）、避免大陣列、多筆小訊息批次成一則。
7. 獨立 callback 要並行 → MultiThreadedExecutor + 不同 callback group（Python 受 GIL 限制）。rclcpp 可試 StaticSingleThreadedExecutor 或 EventsExecutor（實驗性）。
8. 熱路徑改 rclcpp，通常提升最大（rclpy 每則訊息開銷明顯較高）。
9. 同 process 零複製（只有 rclcpp）：`rclcpp::NodeOptions().use_intra_process_comms(true)`，publish `std::unique_ptr`，subscription 也收 unique_ptr。
10. 減少 hop：A→B→C 合成一個 process。
11. 找熱點：`python3 -m cProfile -s cumtime x.py`；callback 內別重複配置物件。
12. 量測時關掉多開的 echo / hz。
延遲組成：publish → 序列化 → DDS → 反序列化 → executor 排隊 → callback；Python 與排隊通常是大頭。

## L09-04

【參考卡｜主機↔MCU 4/8｜協定框架：COBS 與標頭】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
適用：Pico 2（RP2350）↔ Linux 的二進位串流。
建議 frame = COBS( header + payload + CRC16_LE ) + 0x00。
COBS 規則：把資料切成「最多 254 個非零 byte + 一個 0」的組；每組前放一碼 = 該組非零 byte 數 + 1，刪掉那個 0；碼 0xFF = 254 個非零、後面沒有隱含的 0。最後補 0x00 當分隔。開銷 ⌈n/254⌉ B + 1。壞 frame 在下一個 0x00 重新同步。
範例：
- `00` → `01 01 00`
- `00 00` → `01 01 01 00`
- `11 22 00 33` → `03 11 22 02 33 00`
- `11 22 33 44` → `05 11 22 33 44 00`
- `11 00 00 00` → `02 11 01 01 01 00`
標頭（10 B，little-endian，Python `struct.Struct('<BBHIH')`）：
- 0 u8 ver：協定版本，不認得就丟
- 1 u8 type：1=SAMPLE、2=PING、3=PONG、4=CMD
- 2 u16 seq：16-bit 回繞；遺失數 = `(seq - last - 1) & 0xFFFF`；每種 type 各自計數
- 4 u32 t_us：裝置 `time_us_32()`（約 71.6 分鐘回繞），主機可算實際取樣率與 jitter
- 8 u16 len：payload 長度，與實際長度比對
- 10+len u16：CRC-16，涵蓋 offset 0..10+len-1
其他框架：SLIP（END=0xC0，0xC0→DB DC、0xDB→DB DD，最壞 2 倍）；sync+長度（`AA 55 len payload crc`，驗證失敗只丟 1 byte 再找 sync，必須有 CRC，max_len 越小越好）；固定長度不建議（錯一個 byte 之後全錯位）。
文字 vs 二進位：除錯用文字（printf + 主機 split）；效能用二進位（16 個 int16 約 46 B vs 文字 32–112 B）。兩者不要混在同一條串流。
ACK：感測串流只用 seq 統計遺失；指令用 stop-and-wait + 逾時重送（逾時 > RTT p99）+ 接收端依 seq 去重。USB CDC 線路錯誤極少，真正會丟的是緩衝溢位 / 逾時丟棄 / 重新列舉。

## L09-05

【參考卡｜主機↔MCU 5/8｜CRC、位元組序、struct】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
適用：Pico 2（RP2350，ARM 與 RISC-V 皆 little-endian）↔ Linux（也是 little-endian）。
CRC-16/CCITT-FALSE：poly 0x1021、init 0xFFFF、不反射、xorout 0；check("123456789") = 0x29B1。
```c
uint16_t crc16_ccitt(const uint8_t *p, size_t n) {
  uint16_t crc = 0xFFFF;
  while (n--) {
    crc ^= (uint16_t)(*p++) << 8;
    for (int i = 0; i < 8; i++)
      crc = (crc & 0x8000) ? (uint16_t)((crc << 1) ^ 0x1021) : (uint16_t)(crc << 1);
  }
  return crc;
}
```
- Python：`binascii.crc_hqx(data, 0xFFFF)`（init 0 則是 CRC-16/XMODEM）。
- CRC-32（zlib）：反射 poly 0xEDB88320、init / xorout 0xFFFFFFFF；check = 0xCBF43926 = `zlib.crc32(data)`。
- 兩端參數必須完全一致，先用 "123456789" 互驗。RP2350 DMA sniffer 可算 CRC，但與軟體版一致所需的 seed / invert / reverse 組合 ⚠️未驗證，先比對 check 值。
位元組序：
- 協定明訂 little-endian；C 端逐 byte 序列化（`p[0] = (uint8_t)v; p[1] = (uint8_t)(v >> 8);`），不 memcpy struct。
- `struct { uint8_t a; uint32_t b; uint16_t c; }` 的 sizeof = 12；packed = 7。Hazard3 對未對齊 load/store 產生例外。
Python struct：
- `<` little、不對齊（協定用這個）；`@`（預設）有對齊但結尾不補：`struct.calcsize('@BIH')` = 10，與 C 的 12 不同；`'<BIH'` = 7。
- `array.array('h', payload)` 一次把 bytes 變 int16 陣列（本機序 = little）。

```c
if (used >= 1024 || (used && time_us_32() - t_first >= 2000)) {
    stdio_put_string((const char *)txbuf, (int)used, false, false);

}
```
優化清單（大→小）：
1. 先量：吞吐 bytes/s、frames/s 加 ok / lost / crc 計數；RTT 用 PING/PONG，報 min / median / p99。
2. 關掉不需要的 stdio driver（UART 與 USB 同開會被拖慢）。

4. 批次寫出：多個 frame 一次 `stdio_put_string`；主機一次 `read(in_waiting)`。

7. 主機：`struct.Struct` 預編譯、`array.array('h', payload)`、多 frame 併一則 ROS 訊息。
8. 延遲優先：減小批次、reader thread + 小 timeout。
9. UART：提高 baud（兩端同改），接收用 IRQ / DMA。
每次優化後重量，確認 crc / cobs / lost 沒增加（快但錯 = 0 分）。

| 迴圈條件 strlen(s)、反覆 strcat | 先算長度 / 記住尾端 | — |

單執行緒 / 單一 ISR 版。索引持續遞增、取用時 mask；可用滿 N 格。
```c
#include <stdint.h>
#include <stdbool.h>
#define RB_N 256u                         // 必須是 2 的冪
_Static_assert((RB_N & (RB_N - 1)) == 0, "RB_N must be power of 2");
typedef struct { uint8_t buf[RB_N]; uint32_t head, tail; } rb_t;   // head 寫、tail 讀
static inline uint32_t rb_count(const rb_t *r) { return r->head - r->tail; }  // 無號減法，溢位仍正確
static inline bool rb_put(rb_t *r, uint8_t v) {
    if (r->head - r->tail == RB_N) return false;      // 滿
    r->buf[r->head & (RB_N - 1)] = v; r->head++; return true;
}
static inline bool rb_get(rb_t *r, uint8_t *v) {
    if (r->head == r->tail) return false;             // 空
    *v = r->buf[r->tail & (RB_N - 1)]; r->tail++; return true;
}
```
- 另一種設計：索引留在 0..N-1、空一格區分滿/空（容量 N-1）。改寫舊程式要保持容量與「滿時」行為（丟新 / 覆蓋舊 / 回傳失敗）。
- N 不是 2 的冪：`if (++i == N) i = 0;` 比 % 快。
- 寫端讀端在 ISR 與主迴圈、或兩個核心：要 atomic + memory order（SPSC lock-free）；RP2350 跨核可用 pico-sdk 的 queue_t。
- 批次取出：連續區段 `min(count, N - (tail & (N-1)))` 用 memcpy。
雙緩衝：DMA/ISR 填 fill，CPU 處理 work，兩者都完成後「交換指標」不是 memcpy：`int16_t *t = fill; fill = work; work = t;`。處理時間必須 < 填滿時間，否則三緩衝或加大區塊。

【參考卡｜演算法 4/8｜CRC-32/ISO-HDLC 程式碼（逐位元與查表，已測試）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
參數：poly 04C11DB7（反射 EDB88320）、init FFFFFFFF、反射、xorout FFFFFFFF、check("123456789") = 0xCBF43926。
```c
// (a) 逐 bit（無表；每 byte 8 次迴圈）
uint32_t crc32_bitwise(const uint8_t *p, size_t n) {
    uint32_t crc = 0xFFFFFFFFu;
    while (n--) {
        crc ^= *p++;
        for (int k = 0; k < 8; k++)
            crc = (crc >> 1) ^ (0xEDB88320u & -(crc & 1u));
    }
    return crc ^ 0xFFFFFFFFu;
}
// (b) 256 項查表（1 KB；每 byte 1 次查表）
static uint32_t crc32_tab[256];
void crc32_init(void) {
    for (uint32_t i = 0; i < 256; i++) {
        uint32_t c = i;
        for (int k = 0; k < 8; k++) c = (c & 1u) ? (c >> 1) ^ 0xEDB88320u : (c >> 1);
        crc32_tab[i] = c;
    }
}
// 可分段：crc = crc32_update(0, p1, n1); crc = crc32_update(crc, p2, n2);（同 zlib.crc32）
uint32_t crc32_update(uint32_t crc, const uint8_t *p, size_t n) {
    crc = ~crc;
    while (n--) crc = (crc >> 8) ^ crc32_tab[(crc ^ *p++) & 0xFFu];
    return ~crc;
}
```
- 選擇：bitwise（flash 極小）→ 256 表（預設）→ slicing-by-4（4 KB 表，主機大資料；MCU 表要放 SRAM）。
- 建表放在計時區外，但先確認計分是否包含初始化。

【參考卡｜演算法 6/8｜Hash table（open addressing，已測試）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
```c
#define HT_BITS 10
#define HT_SIZE (1u << HT_BITS) // 1024 槽；最多放約 0.7*HT_SIZE 筆
#define EMPTY_KEY 0xFFFFFFFFu // 保留一個不會出現的 key 當「空」
typedef struct { uint32_t key; int32_t val; } slot_t;
static slot_t ht[HT_SIZE];
static void ht_init(void) { for (uint32_t i = 0; i < HT_SIZE; i++) ht[i].key = EMPTY_KEY; }
// Fibonacci hashing：乘 2654435769 (0x9E3779B9)，取「高」HT_BITS 位
static inline uint32_t hash32(uint32_t k) { return (k * 2654435769u) >> (32 - HT_BITS); }
static int32_t *ht_get_or_insert(uint32_t key, bool *inserted) {
    uint32_t i = hash32(key);
    for (uint32_t probe = 0; probe < HT_SIZE; probe++) {
        if (ht[i].key == key)       { *inserted = false; return &ht[i].val; }
        if (ht[i].key == EMPTY_KEY) { ht[i].key = key; ht[i].val = 0; *inserted = true; return &ht[i].val; }
        i = (i + 1) & (HT_SIZE - 1);
    }
    return NULL; // 表滿
}
```

- 取高位：取低位 `k & mask` 對有規律的 key（如 1024 的倍數）會全撞。
- 刪除不能直接設 EMPTY（切斷探測鏈）→ tombstone。
- 字串 key：FNV-1a 32（h=0x811C9DC5；`h ^= b; h *= 0x01000193;`）再比字串本身。

```c
// 第一個 a[i] >= x 的 i（全都 < x 回傳 n）；a 已遞增排序
static size_t lower_bound(const int32_t *a, size_t n, int32_t x) {
    size_t lo = 0, hi = n;                       // 半開 [lo, hi)
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < x) lo = mid + 1; else hi = mid;
    }
    return lo;
}
// upper_bound（第一個 > x）：條件改 a[mid] <= x；出現次數 = upper - lower
```
- 例：a={1,2,2,2,5,7}：lower_bound(2)=1、upper_bound(2)=4、lower_bound(8)=6。

```c
static int dq[MAXN]; int head = 0, tail = 0;     // 容量 >= n
for (int i = 0; i < n; i++) {
    while (tail > head && a[dq[tail - 1]] >= a[i]) tail--;
    dq[tail++] = i;
    if (dq[head] <= i - w) head++;
    if (i >= w - 1) out[i - w + 1] = a[dq[head]];
}
```
最大值版把 >= 改 <=。要輸出索引時 >= 保留最右、> 保留最舊，要和原程式一致。

【參考卡｜演算法 8/8｜排序事實與「優化後輸出完全相同」檢查】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
排序：
- C qsort：不保證 quicksort、不保證複雜度、不穩定。比較函式寫 `return (a > b) - (a < b);`，不要 `a - b`（溢位 UB）。要確定結果時把原始索引當最後一個鍵。
- C++ std::sort：C++11 起最壞 O(N log N)、不穩定；stable_sort 穩定；nth_element 平均 O(N)。Python sorted 穩定。
- n ≤ 約 16 或幾乎排好 → insertion sort；radix sort 有號數先 `^ 0x80000000`，跑偶數趟（4 趟）。
等價檢查（每改一處都做）：
- 原程式產生 golden output，新版 diff/cmp；寫隨機產生器對拍幾千組。
- 邊界：n=0（size_t 的 n-1 下溢）、n=1、2、最大 n（佇列 / heap 容量 ≥ E+1、stack 深度）。
- 溢位：和、乘積、平方距離、`INF + w`。
- 有號：`x >> k` 與 `x / 2^k` 對負數不同（-7/2=-3，-7>>1=-4）；% 的符號。
- Tie：排序穩定性、heap 彈出順序、top-k 同分取誰、argmin 取第一或最後。
- 走訪順序：hash 表、迭代 DFS 與遞迴 DFS 順序不同。
- 浮點：重排加法、多累加器、乘倒數都會改末位；要逐位元相同就不動運算順序。
- 副作用：新版（quickselect、原地排序）是否多改了輸入陣列；「找不到」回傳值相同。
- CRC：對 "123456789" check value 與原程式輸出各比一次。
主機檢查 UB：`gcc -O2 -fsanitize=address,undefined`。

```c
    *out = (int)(neg ? -v : v);
    return 1;
}
```

10. MultiThreadedExecutor 期待 CPU 加速 → GIL；callback 都在預設 group 時仍一次一個。

- 同一組輸入（含邊界 0、1、-1、2³⁰、2³¹-1、-2³¹）比對優化前後輸出逐筆一致（echo 或測試 subscriber 存檔後 `diff`）。

## L13-01

【參考卡｜平行 1/8｜決策：值不值得平行化】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
情境：Linux 容器（Ubuntu 24.04、GCC 13）上的 C 程式，judge 量執行時間。
步驟：
1. 可用核心：`nproc`；`cat /sys/fs/cgroup/cpu.max`（"quota period"，max = 不限）。容器用 quota 限制時 nproc 可能仍顯示全部核心 → 手動設執行緒數。
2. judge 量 wall time 還是 CPU time？（⚠️考場規則未知）量 CPU time 時平行化不會變快，忙等更差。
3. 量 serial 版：p = 熱點時間 / 總時間。Amdahl 上限 1/(1−p)。
4. 每份工作要遠大於 parallel region 啟動 + barrier（微秒級，⚠️自己量），至少大兩個數量級。
5. 迴圈第 i 次用到第 i−1 次結果 → 不能直接 parallel for（scan、wavefront 或改演算法）。
6. 驗證：輸出與 serial 逐位元相同，多次執行一致。
| 觀察 | 結論 |
|---|---|
| nproc=1 或 judge 限 1 核 | 不平行；改演算法、cache、I/O |
| 熱點是 I/O | 批次 I/O、緩衝、I/O 與計算重疊，不是加運算執行緒 |
| 熱點是記憶體頻寬（每 byte 一兩個運算） | 多核收益有限 |
| 獨立大量運算 | 資料平行，接近線性 |
| 共享累加 | 歸約：各自累加、最後合併 |
Amdahl S = 1/((1−p)+p/N)：p=0.9 時 N=4 → 3.08、N=8 → 4.71、N=∞ → 10；p=0.5 時無限核心也只有 2 倍。
Karp–Flatt e = (1/S − 1/N)/(1 − 1/N)：N 變大 e 不變 → 瓶頸是序列部分；e 變大 → 開銷（同步、通訊、不平衡）在成長。
加速比基準 T1 用最佳 serial 版，不是平行版開 1 執行緒。

## L13-02

【參考卡｜平行 2/8｜分解模式與分割方式】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
| 模式 | 適用 | 主要風險 |
|---|---|---|
| 資料平行 map | 陣列、影像、多筆獨立測資 | 記憶體頻寬、不平衡 |
| 歸約 reduction | sum/max/直方圖 | 共享累加變數 race、競爭 |
| Scan / prefix sum | 壓縮、分配位置 | 兩趟 block scan 可平行 |
| 流水線 pipeline | 串流、感測→處理→輸出、ROS 2 node 鏈 | 最慢 stage、佇列成長 |
| fork–join tasks | 分治、遞迴 | 任務太小 → 要 cutoff |
| master–worker 工作佇列 | 工作大小不一 | 佇列成為熱點 |
| stencil + halo | 影像濾波、Jacobi | 邊界交換、每步同步 |
| embarrassingly parallel | 參數掃描、Monte Carlo | 種子、輸出順序 |
歸約三種寫法：每次 critical（幾乎一定比 serial 慢）< 每次 atomic（同一 cache line 在核心間彈跳，常仍比 serial 慢）< 每執行緒區域累加、結尾合併一次（正解）。
分割（T 個執行緒，第 t 個）：
| 分割 | 範圍 | OpenMP |
|---|---|---|
| Block | `[n*t/T, n*(t+1)/T)`（先乘再除，n 大用 long long） | schedule(static) |
| Cyclic | i = t, t+T, … | schedule(static,1) |
| Dynamic | 誰閒誰拿 B 個 | schedule(dynamic,B) |
| Guided | 大塊漸小 | schedule(guided,B) |
- 本機實測三角形負載（成本 ∝ i，8 緒）：static 0.42 s、static,1 0.29 s、dynamic,64 0.26 s；成本均勻時 static 開銷最小。
- 粒度：任務數 ≈ 核心數 × 4–16，每任務至少數十微秒（⚠️經驗值）。多筆大小不同的工作：大的先排。

## L13-03

【參考卡｜平行 3/8｜OpenMP 基礎：編譯、parallel for、schedule、變數共享】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
情境：Ubuntu 24.04 GCC 13（libgomp）。
- 編譯與連結都要 `gcc -O2 -fopenmp`；`OMP_NUM_THREADS=4 ./x`。沒加 -fopenmp 時 pragma 被忽略、單執行緒跑（-Wall 出現 -Wunknown-pragmas）；omp_* 呼叫會連結失敗 → 用 `#ifdef _OPENMP`。
- GCC 13 的 _OPENMP = 201511（4.5）；masked、陣列區段 reduction、taskloop、parallel for simd 實測可用。
- 裝了 gcc 就有 omp.h（libgcc-13-dev 依賴 libgomp1）；⚠️未在考場容器實測，先試編。
```c
#pragma omp parallel for schedule(static) num_threads(4) if(n > 10000)
for (long i = 0; i < n; i++) out[i] = f(in[i]);
```
- if(expr) 為假 → 單執行緒，小輸入不平行。迴圈內不能 break（可 continue）。
- schedule：static 不給 chunk = 等長連續塊；dynamic 不給 chunk 預設 1（太小，試 16–1024）；guided 漸小；runtime 讀 OMP_SCHEDULE（libgomp 未設定時 dynamic,1）；沒寫 schedule 時 GCC 13 實測展開成 static。
- 第一個 parallel region 付建立執行緒成本 → 先熱身再計時。
變數共享：
- private 未初始化；firstprivate 複製初值；lastprivate 取序列上最後一次迭代的值。
- 建議 `default(none)`，強迫每個變數明確標示。
- C 經典 bug：內層迴圈變數宣告在 parallel 外面 = shared → race。
```c
#pragma omp parallel for        // 對：在迴圈內宣告
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++) a[i][j] = 0;
```

## L13-04

【參考卡｜平行 4/8｜OpenMP：reduction、同步、tasks、環境變數】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
情境：GCC 13 libgomp。
```c
#pragma omp parallel for reduction(+:s) reduction(max:mx)
for (long i = 0; i < n; i++) { s += a[i]; if (b[i] > mx) mx = b[i]; }
#pragma omp parallel for reduction(+:hist[:256])   // 陣列區段 reduction（GCC 13 實測可用）
for (long i = 0; i < n; i++) hist[data[i]]++;
```
- 合併順序未指定 → 浮點總和隨執行緒數改變。陣列 reduction 每執行緒一份完整副本（大陣列可能爆 stack → 放 heap、OMP_STACKSIZE）。
| 構造 | 注意 |
|---|---|
| critical | 重；沒名字的全部共用一把鎖 |
| atomic | 單一位置 x++ / x += expr，比 critical 輕 |
| barrier | 不能放在只有部分執行緒會走到的分支（deadlock） |
| nowait | 去掉 for/single 結尾隱含 barrier；後面要用結果就不能加 |
| single | 任一執行緒執行，結尾有 barrier |
| masked / master | 只 thread 0，沒有 barrier |
| ordered | 依迭代順序，會序列化那段 |
- collapse(2)：完美巢狀矩形迴圈合併，外層很小時有用。`parallel for simd`：執行緒 + 向量化。
- tasks：`#pragma omp parallel` + `#pragma omp single` 產生根任務；`task shared(a)` 寫回結果；`taskwait` 等直接子任務。沒有 cutoff（如 n < 20 改 serial）會比 serial 慢很多。
- API：omp_get_wtime、omp_get_thread_num、omp_get_num_threads、omp_get_max_threads（配置 per-thread 陣列用）。
- 環境變數：OMP_NUM_THREADS、OMP_PROC_BIND、OMP_PLACES、OMP_DISPLAY_ENV=true（確認生效）。巢狀預設只 1 層 active。超額訂閱時用 OMP_WAIT_POLICY=PASSIVE。

【參考卡｜平行 5/8｜OpenMP 直方圖實測：熱迴圈內不要同步】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
本機實測（x86-64、GCC 13.3、-O2 -fopenmp、N=2^26 bytes、256 bins；只看相對關係）：
| 版本 | 1 緒 | 4 緒 | 12 緒 |
|---|---|---|---|
| serial | 0.018 s | — | — |
| 每次 atomic | 0.125 | 0.399 | 0.191 |
| 每次 critical | 0.274 | 4.3 | 12.1 |
| per-thread local + 合併 | 0.018 | 0.005 | 0.004 |
| reduction(+:h[:NB]) | 0.032 | 0.008 | 0.006 |
所有版本結果與 serial 完全相同（整數加法）。
per-thread 寫法：
```c
#pragma omp parallel
{
    long local[NB] = {0};                 // region 內宣告 → private
    #pragma omp for nowait                // 合併不需等別人做完迴圈
    for (long i = 0; i < N; i++) local[data[i]]++;
    for (int b = 0; b < NB; b++) {
        #pragma omp atomic
        h_local[b] += local[b];
    }
}                                         // region 結尾隱含 barrier
```
- bin 很多（如 2^20）：副本放 heap `calloc(T*NB)`，T = omp_get_max_threads()。
- `long part[T][NB]` 且 NB 很小：相鄰執行緒同一 cache line → false sharing；每列補到 64 bytes 倍數，或改區域變數累加。
- 計時用 omp_get_wtime()，印到 stderr。

## L13-06

【參考卡｜平行 6/8｜確定性輸出：平行版和 serial 一模一樣】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
judge 用 diff 比對輸出時必看。
| 問題 | 修法 |
|---|---|
| 輸出行順序隨機 | 平行計算 → 存 out[i] → 序列依 i 輸出（或 ordered，會序列化） |
| stdout 交錯、半行 | 只讓一個執行緒 / rank 0 輸出 |
| 浮點總和末位不同 | 固定大小分塊（與執行緒數無關），各塊存 part[b]，依 b 順序加總 |
| 整數偶爾錯 | data race → reduction / per-thread partial |
| 隨機數不同 | 每個「工作項」用由索引推導的種子；rand() 改 rand_r |
| hash map 合併順序不同 | 合併後排序再輸出 |
| 計時混進 stdout | 計時印 stderr |
```c
#define B 4096                                      // 固定塊大小，與執行緒數無關
long nb = (n + B - 1) / B;
double *part = malloc(nb * sizeof *part);
#pragma omp parallel for schedule(static)
for (long b = 0; b < nb; b++) {
    double s = 0;
    long hi = (b + 1) * B < n ? (b + 1) * B : n;
    for (long i = b * B; i < hi; i++) s += a[i];
    part[b] = s;
}
double total = 0;
for (long b = 0; b < nb; b++) total += part[b];    // 順序固定 → 結果固定
```
- 注意：與完全序列 `s += a[i]` 仍可能差末位；必須逐位元同 serial 參考時，serial 版也要用同樣分塊，或題目允許誤差。
- 多 process：fork 前 `fflush(stdout)`；子 process 把結果寫到 `MAP_SHARED|MAP_ANONYMOUS` 的 res[k]，用 `_exit(0)` 結束；父 `while (wait(NULL) > 0) {}` 後依 k 輸出。

## L13-08

【參考卡｜平行 8/8｜通訊成本、流水線、IPC、ROS 2】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
通訊 α–β 模型：T(n) = α + β·n（α 每則固定延遲，β = 1/頻寬）。
- k 則小訊息合成 1 則 → 省 (k−1)·α：批次化。
- 頻寬受限 → 二進位取代文字、較小型別、只傳差異。
- 例：UART 115200 baud 8N1 每 byte ≈ 86.8 µs，每筆 printf 20 字元 ≈ 1.7 ms → 輸出本身是瓶頸；MCU 先歸約、二進位批次。
流水線（k stage，每 stage t_i）：吞吐量 ≈ 1/max(t_i)；單筆延遲 = Σt_i；加速上限 = Σt_i / max(t_i) ≤ k。平衡做法：拆最慢 stage，或無狀態 stage 多個 worker。
Little's law L = λW。佇列持續成長 → 下游比上游慢。有界佇列 = backpressure。要低延遲 → 小批次、淺佇列、丟舊留新；要總時間短 → 大批次、深佇列。
IPC：
- pipe：Linux 預設容量 65536 bytes；≤ PIPE_BUF（4096）的 write 是原子的；read/write 可能只做部分 → 迴圈；不用的端要關，否則等不到 EOF。
- 共享記憶體：`shm_open("/name", O_CREAT|O_RDWR, 0600)` + ftruncate + mmap(MAP_SHARED)；glibc ≥ 2.34 不需 -lrt；要自己同步。
- MPI 考場多半沒裝（`which mpicc`）。
ROS 2（Jazzy）：
- 一個 process 一個 DDS participant → 同 process 多 node 較省；component container + `use_intra_process_comms:=true`（rclcpp only）省序列化。
- 逐段 `ros2 topic hz` 找頻率掉的 stage；`ros2 topic delay` 需要 header.stamp。
- topic 沒有端到端 backpressure；低延遲用 KEEP_LAST 小 depth；高頻小訊息改陣列批次。

【參考卡｜控制DSP 1/8｜平台選擇與定點格式（RP2350）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2，非 RP2040），兩種核心可選：
- Hazard3（RISC-V）：無 FPU，float 全部軟體模擬 → 用定點數。mul/mulh 各 1 cycle、div 18–19 cycle（⚠️未查證，見 datasheet 3.8.7），有 Zbb min/max/clz。
- Cortex-M33：單精度 FPU，可用 float，不要 double（常數寫 1.0f）；DSP 指令 SMLAD（兩個 16×16 乘加）、SSAT、SMMUL。
- 兩核都沒有 64-bit 除法指令（軟體函式：Arm `__aeabi_ldivmod`、RISC-V `__divdi3`，很慢）。
- Hazard3 執行期 float↔定點轉換是軟體浮點，只在初始化做；fix2float/float2fix 只在 Arm 版 pico_float 有。
- 要和 judge 逐位元一致 → 定點 + 固定捨入規則（float 會因 FMA、旗標、平台差末位）。
定點：實際值 = raw / 2^FRAC。寫程式時用「容器型別 + FRAC」描述最不會錯。
| 名稱 | 容器 | FRAC | 範圍 | 用途 |
|---|---|---|---|---|
| Q15 | int16_t | 15 | [−1, 0.999969] | ADC/音訊樣本、係數 |
| Q2.14 | int16_t | 14 | [−2, 2) | biquad 係數 |
| Q31 | int32_t | 31 | [−1, 1) | 高精度係數 |
| Q2.30 | int32_t | 30 | [−2, 2) | biquad 係數（a1 可近 ±2） |
| Q16.16 | int32_t | 16 | [−32768, 32768) | 通用物理量 |
| UQ0.32 | uint32_t | 32 | [0, 1) | 相位累加器，一圈 2^32 |
- Q15 不能表示 +1.0，常數 1.0 寫 32767。
- 角度可用 binary angle（uint16/uint32 全範圍 = 2π），自然繞回。
- 選格式：列出每個變數最大絕對值 → 整數位 = ceil(log2(max)) + 1 符號位 + 1–2 保護位 → 其餘給小數 → 每個乘法/累加算位元增長決定 int32 或 int64 → 只在輸出飽和 → 主機與 double 比對。

## L15-02

【參考卡｜控制DSP 2/8｜定點乘法與轉換（C，主機已驗證）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
適用 RP2350 Hazard3 / Cortex-M33 與主機，只用 <stdint.h>。規則：先放大到 64 位元再移位。
```c
#define Q16(x) ((q16_t)((x) * 65536.0 + ((x) >= 0 ? 0.5 : -0.5)))  // 編譯期常數，四捨五入
static inline int16_t sat16(int32_t x) { return x > 32767 ? 32767 : (x < -32768 ? -32768 : (int16_t)x); }
static inline int32_t sat32(int64_t x) { return x > INT32_MAX ? INT32_MAX : (x < INT32_MIN ? INT32_MIN : (int32_t)x); }
static inline int16_t q15_mul(int16_t a, int16_t b) {
    int32_t p = (int32_t)a * b;
    return sat16((p + (1 << 14)) >> 15);     // (-1)×(-1) 飽和成 32767
}
static inline int32_t q16_mul(int32_t a, int32_t b) {
    return (int32_t)(((int64_t)a * b + (1 << 15)) >> 16);
}
static inline int32_t q31_mul(int32_t a, int32_t b) {
    return sat32(((int64_t)a * b + (1LL << 30)) >> 31);
}
static inline q16_t q16_from_int(int32_t i) { return (q16_t)((uint32_t)i << 16); } // 左移負數是 UB
static inline int32_t q16_to_int_round(q16_t a) { return (a + (1 << 15)) >> 16; }
```
（q16_t 為 int32_t。）驗證：q15_mul(-32768,-32768)=32767、q16_mul(1.5,-2.25)=-3.375、q31_mul(0.5,0.5)=0.25。
- 最常見錯誤：`(int64_t)(a * b)` 括號錯，a*b 先以 32 位元溢位（UB）。正確是 `(int64_t)a * b`。

## L15-03

【參考卡｜控制DSP 3/8｜捨入、除法、溢位與數值陷阱】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
情境：RP2350（Hazard3 / M33）或主機上的定點 C 程式。
捨入：CMSIS-DSP arm_mult_q15 是截斷再飽和（要一致就別加捨入）。`x >> n` 往 −∞（平均偏 −0.5 LSB，長期累加漂移）；C 的 `/` 往 0；最常用四捨五入 `(x + (1 << (n-1))) >> n`。`-7 / 2 = -3`，`-7 >> 1 = -4`。
除法：
- 除以 2^k 用移位；除以編譯期常數直接寫，編譯器轉乘法。
- 同一個變數 d 要除很多次 → 倒數乘法（主機已驗證，x·d ≤ 2^32 時與 x/d 完全相同）：
```c
static inline uint32_t recip_u32(uint32_t d) { return (uint32_t)(((1ull << 32) + d - 1) / d); }  // d >= 2，初始化算一次
static inline uint32_t div_by_recip(uint32_t x, uint32_t inv) { return (uint32_t)(((uint64_t)x * inv) >> 32); }
```
位元增長：加兩個 n-bit → n+1；N 項和 → +ceil(log2 N)；n×m → n+m；FIR 更緊界 |y| ≤ max|x|·Σ|h|。
陷阱：
- 有號溢位、負數左移是 UB → int64、無號累加、乘法 `x * (1 << n)`。
- 溢位繞回：最大正數 + 1 = 最大負數（馬達反轉）→ 輸出處飽和；內部累加器用夠寬型別。
- `char` 在 Arm 與 RISC-V 預設無號、x86 有號；`long` 在 RP2350 32 位、x86-64 Linux 64 位 → 用 int8_t、int32_t。
- float 只有 24 位尾數：16777216.0f + 1.0f == 16777216.0f；時間用整數 µs。
- 隱性 double：`x * 0.5`、`sin()`、`printf("%f")` → 常數加 f、`-Wdouble-promotion`。
- Hazard3 div 除以 0 不 trap（回傳 −1），C 為 UB → 先檢查。
- 抓隱性浮點/64 位除法：objdump 找 RISC-V `__mulsf3`、`__adddf3`、`__divdi3`；Arm `__aeabi_dadd`、`__aeabi_ldivmod`。

## L15-04

【參考卡｜控制DSP 4/8｜便宜濾波器：EMA、移動平均、中值（C，主機已驗證）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
EMA / 一階低通：`y[n] = y[n−1] + α(x[n] − y[n−1])`。α = 2^−k 時時間常數約 2^k 樣本，不需乘法；α ≈ Ts/(τ+Ts)；fc ≈ α·fs/(2π)。
```c
// 狀態 acc 帶 k 位額外小數（acc = y·2^k），避免截斷造成穩態誤差
typedef struct { int32_t acc; } ema_t;   // 初始化：acc = 第一筆樣本 * (1 << k)
static inline int32_t ema_step(ema_t *f, int32_t x, int k) {
    f->acc += x - (f->acc >> k);
    return f->acc >> k;
}
```
- 錯誤寫法：`y += (x - y) >> k;` 實測 k=4 從 0 往 1000 收斂卡在 985，往負方向卻到 -1000（不對稱偏差）。
- 16-bit 輸入、k ≤ 15 時 acc 用 int32 安全。高通 = x − 低通。
移動平均（N = 2^k，O(1)，整數永遠精確）：
```c
#define MA_BITS 4
#define MA_N (1 << MA_BITS)
typedef struct { int16_t buf[MA_N]; int32_t sum; uint32_t i; } ma_t;   // 全部初始化為 0
// ma_step(ma_t *m, int16_t x) 本體：
m->sum += x - m->buf[m->i];
m->buf[m->i] = x;
m->i = (m->i + 1) & (MA_N - 1);
return (int16_t)(m->sum >> MA_BITS);
```
- 第一個零點在 fs/N，可完全抵消週期 N 點的干擾；前 N 點輸出偏小。
中值（去突波，保留步階）：
```c
static inline int32_t med3(int32_t a, int32_t b, int32_t c) {
    int32_t lo = a < b ? a : b, hi = a < b ? b : a;
    int32_t m  = hi < c ? hi : c;
    return lo > m ? lo : m;
}
```
常見組合：median 去突波 → EMA 去高頻。濾波狀態用第一筆樣本初始化。

【參考卡｜控制DSP 5/8｜Biquad 二階 IIR（RBJ 係數 + 定點 DF1）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
係數（RBJ Audio EQ Cookbook，在主機或初始化用 double 算）：
w0 = 2π·f0/fs，alpha = sin(w0)/(2Q)（Butterworth Q = 0.7071）
LPF：b0 = (1−cos w0)/2，b1 = 1−cos w0，b2 = (1−cos w0)/2
HPF：b0 = (1+cos w0)/2，b1 = −(1+cos w0)，b2 = (1+cos w0)/2
共同：a0 = 1+alpha，a1 = −2cos w0，a2 = 1−alpha；全部除以 a0。
y[n] = b0x[n] + b1x[n−1] + b2x[n−2] − a1y[n−1] − a2y[n−2]
例：fs=1kHz、f0=10Hz → b0=0.000944691、a1=−1.911196288、a2=0.914975054（a1 近 −2 → 係數格式要能表示 ±2）。
定點 DF1（bq_q30_step 本體；係數 b0..a2 為 Q2.30、a1/a2 用 RBJ 正規化值未取負；x1,x2 為 int16 樣本；y1,y2 為 Q16 且 |y| < 32768；累加器 int64）：
```c
int64_t acc = ((int64_t)f->b0 * x + (int64_t)f->b1 * f->x1 + (int64_t)f->b2 * f->x2) * 65536
            - (int64_t)f->a1 * f->y1 - (int64_t)f->a2 * f->y2;   // Q46
int32_t y = (int32_t)((acc + (1 << 29)) >> 30);                    // Q46 → Q16
f->x2 = f->x1; f->x1 = x;
f->y2 = f->y1; f->y1 = y;
return sat16((y + (1 << 15)) >> 16);
```
- 實測（f0/fs=0.01）：y 狀態只存整數誤差 111.6 LSB；保留 16 位額外小數 0.5 LSB。極點越靠近 1 越要保留。
- ⚠️ int64 不溢位的估計只針對低通；高通 b 係數接近 ±1、±2 要重新估算或先縮小輸入。
- 浮點（M33）用 Transposed DF2；定點用 DF1。4 階以上拆成多個 biquad 串接。
- CMSIS-DSP biquad 回授項是加號 → RBJ 的 a1、a2 要取負號再給。pico-sdk 沒內附 CMSIS-DSP。

## L15-06

【參考卡｜控制DSP 6/8｜離散 PID 程式碼（float，M33 或主機）】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
I[n] = I[n−1] + Ki·dt·e（積分存已乘 Ki 的值，線上改 Ki 不跳）；D = −Kd·(y[n]−y[n−1])/dt（微分取量測值，避免 setpoint 跳動的 derivative kick）；u = sat(Kp·e + I + D)。
```c
typedef struct {
    float kp, ki_dt, kd_div_dt;      // 預先算好 ki*dt、kd/dt
    float d_alpha;                   // 微分低通係數，0 < d_alpha ≤ 1（1 = 不濾波）
    float out_min, out_max;
    float i, d, y_prev;
    int   first;
} pid_ctrl_t;
float pid_step(pid_ctrl_t *p, float r, float y) {
    if (p->first) { p->y_prev = y; p->first = 0; }
    float e = r - y;
    float d_raw = -p->kd_div_dt * (y - p->y_prev);
    p->d += p->d_alpha * (d_raw - p->d);
    p->y_prev = y;
    float i_new = p->i + p->ki_dt * e;
    float u = p->kp * e + i_new + p->d;
    // anti-windup（條件積分）：飽和且誤差會讓它更飽和時不更新積分
    if (u > p->out_max)      { u = p->out_max; if (e < 0) p->i = i_new; }
    else if (u < p->out_min) { u = p->out_min; if (e > 0) p->i = i_new; }
    else                     { p->i = i_new; }
    return u;
}
```
- 名稱避開 POSIX 的 pid_t。第一次呼叫令 y_prev = y，避免微分突波。
- Hazard3（無 FPU）改整數版：增益 Q16.16、積分 int64；Ki·dt 太小量化成 0 時積分用更多小數位（如 Q24）。

## L15-07

【參考卡｜控制DSP 7/8｜PID：anti-windup、增量式、調參、時序】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
anti-windup（飽和期間積分持續累積 → 解除後大超調）三種做法：
(a) 條件積分：輸出飽和且 e 會讓它更飽和時不積分。
(b) 積分項本身夾在 [out_min, out_max]。
(c) back-calculation：`i += ki_dt*e + (dt/Tt)*(u_sat − u_unsat)`，Tt 常取 Ti 或 √(Ti·Td) 量級。
其他元件：微分一階低通（時間常數 Td/N，N ≈ 5–20）；setpoint 斜率限制；bumpless transfer 切換時令 `i = u_current − kp*e − d`。
增量式：Δu = Kp(e−e1) + Ki·dt·e + (Kd/dt)(e − 2e1 + e2)，u = sat(u_prev + Δu)。天然 anti-windup；但 Ki = 0 時輸出偏移會漂移，通常一定要有 I 項。
Ziegler–Nichols（只用 P 加到等幅振盪，得 Ku、Tu）：
| 控制器 | Kp | Ti | Td |
|---|---|---|---|
| P | 0.5Ku | — | — |
| PI | 0.45Ku | Tu/1.2 | — |
| PID | 0.6Ku | Tu/2 | Tu/8 |
Ki = Kp/Ti，Kd = Kp·Td；ZN 超調偏大（約 25%），當起點。手調：先 Kp → 加 Kd 抑制超調 → 加 Ki 消穩態誤差。
時序（經驗）：fs 約閉迴路頻寬 10–30 倍；讀感測器 → 輸出延遲要短且固定；外迴路比內迴路慢 5–10 倍；控制計算最壞時間 < 週期一半。
振盪時查：Kp/Kd 太大、延遲大、dt 與實際週期不符、微分沒濾波、單位錯（deg/rad）。

平台：RP2350（Pico 2），pico-sdk 2.x。
```c
const uint32_t T_US = 1000;                  // 1 kHz
absolute_time_t next = get_absolute_time();
```

12. task 函式不能 return；結束用 `vTaskDelete(NULL)`

## L16-05

【參考卡｜FreeRTOS 5/8｜ISR 規則與中斷優先權】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2）Cortex-M33 port（RP2350_ARM_NTZ），pico-sdk。
```c
void my_irq_handler(void) {
    BaseType_t woken = pdFALSE;
    /* 清中斷旗標、讀硬體 */
    vTaskNotifyGiveFromISR(worker_handle, &woken);
    portYIELD_FROM_ISR(woken);
}
```
規則：
- ISR 只能呼叫 `...FromISR` API（及 `portYIELD_FROM_ISR`、`taskENTER_CRITICAL_FROM_ISR`）；FromISR 不阻塞
- `woken` 一定初始化成 pdFALSE；多個 FromISR 可共用同一個 woken
- 忘了 `portYIELD_FROM_ISR`：被喚醒的 task 要等下次排程 → 延遲變大
- ISR 內的 critical：`UBaseType_t s = taskENTER_CRITICAL_FROM_ISR(); … taskEXIT_CRITICAL_FROM_ISR(s);`
IRQ 優先權（NVIC 高 4 bit 有效，0x00、0x10…0xF0，越小越優先）：
- 0x00（PICO_HIGHEST_IRQ_PRIORITY）：不可呼叫任何 FreeRTOS API；不會被 critical section 遮罩
- 0x10～0xF0（含 SDK 預設 0x80）：可呼叫 FromISR API；會被 critical section 遮罩
- 在 0x00 呼叫 → configASSERT 在 vPortValidateInterruptPriority 失敗
其他：
- 註冊方式不變：`irq_set_exclusive_handler(irq, fn)`、`irq_set_enabled(irq, true)`；GPIO `gpio_set_irq_enabled_with_callback(pin, events, true, cb)`
- IRQ 在哪核啟用就在哪核執行 → 想在 core 1 處理，就在綁 core 1 的 task 裡啟用
- IRQ 用到的 queue / task handle 建立好之後才啟用 IRQ
- 處理中斷的 task 優先權要高（ISR 只清旗標 + notification）
- RISC-V port：不支援巢狀中斷；無 MAX_SYSCALL 優先權，critical 擋全部 IRQ（含 0x00）

## L16-06

【參考卡｜FreeRTOS 6/8｜SMP、綁核、critical section、裸機對照】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
平台：RP2350（Pico 2）FreeRTOS SMP（configNUMBER_OF_CORES 2）。
- port 啟動時 claim 兩把 spinlock（`PICO_SPINLOCK_ID_OS1/OS2`，kernel 專用）與一個 doorbell（跨核 yield），然後自己 `multicore_reset_core1()` + launch
- `configRUN_MULTIPLE_PRIORITIES 1`：不同優先權 task 可同時在兩核跑 → 用優先權當互斥會出錯
- 綁核：`xTaskCreateAffinitySet(..., 1u << 1, ...)`；經典配置 core 0 放 I/O 與通訊、core 1 放純運算；ISR 與處理 task 同核
- 資料平行：每核一個 worker、各自累加，用 event group / notification 等全部完成再合併
- idle task 不綁核（IDLE0 不一定在 core 0）
critical section：
- `taskENTER_CRITICAL(); … taskEXIT_CRITICAL();`：遮本核 IRQ（Arm：BASEPRI 擋 ≥ 0x10；RISC-V：全關）+ 取 OS1/OS2 spinlock，是全系統一把鎖 → 只放幾行，不可呼叫阻塞 API
- 較長操作（printf、走訪 list）用 mutex
- 陷阱：main() 裡第一次 xTaskCreate / xQueueCreate 後，IRQ 被遮罩到第一個 task 開始跑 → 硬體初始化放建立物件前；需要 IRQ 或 sleep_ms 的初始化放進 task
裸機 → FreeRTOS：
- `multicore_launch_core1` → affinity task
- `multicore_fifo_*` → FreeRTOS queue / notification
- `spin_lock_blocking` / `critical_section_*` → `taskENTER_CRITICAL`（極短）或 mutex
- flag 輪詢 → `vTaskNotifyGiveFromISR` + `ulTaskNotifyTake`
- `add_repeating_timer_ms` → `xTaskDelayUntil` 週期 task 或軟體 timer
- pico `queue_t` / `mutex_t` 在 SYNC_INTEROP 下仍可用

【參考卡｜建置 5/7｜CMake 通用：configure、cache、target】
以下是正確的參考資料，若與你的記憶不同，以這張為準。CMake 3.x（pico-build 映像為 3.28）。
- configure：`cmake -B build -D變數=值`（或在 build/ 裡 `cmake ..`）→ 讀 CMakeLists.txt，產生 Makefile，寫入 `build/CMakeCache.txt`
- build：`cmake --build build -j`（= `make -C build -j`）→ 編譯、連結
- 只改 .c → 只要 build；改 CMakeLists.txt → build 時自動重跑 configure
- `-D` 的值記在 cache，之後不寫也沿用。換 PICO_BOARD / PICO_PLATFORM / 工具鏈，或「改了沒效果」→ `rm -rf build` 重來
- 查目前值：`grep -E "PICO_BOARD|PICO_PLATFORM|CMAKE_BUILD_TYPE" build/CMakeCache.txt`
- 看完整編譯指令：`make -C build VERBOSE=1`
- `target_link_libraries(t PRIVATE x)` 只給 t；`PUBLIC` 給 t 和連結 t 的；`INTERFACE` 只給連結 t 的
- 同一 target 的 target_link_libraries 全部寫關鍵字或全部不寫；混用 → configure 錯「All uses of target_link_libraries with a target must be either all-keyword or all-plain」（已實測）
- `target_compile_definitions(t PRIVATE FOO=1)` 只給 t；`add_compile_definitions(FOO=1)` 給此目錄之後所有 target
- 少 link 函式庫 → `fatal error: hardware/dma.h: No such file or directory`（已實測）或 undefined reference
- `undefined reference to 'f'`：f 的 .c 沒加進 add_executable，或沒 link；`multiple definition`：header 裡定義了變數
- pico-sdk 沒指定 build type 時預設 `Release`（-O3）；`Debug` 為 -Og。以 judge 指令為準。

- `target_compile_definitions(t PRIVATE PICO_STDIO_DEFAULT_CRLF=0)`：關 \n→\r\n（二進位必備）。SDK 函式庫是 INTERFACE library，跟 t 一起編，所以也作用在 SDK 的 stdio

## L22-05

【參考卡｜優化 5/6｜瓶頸分類與手法】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
現象 → 瓶頸類型：
- CPU 滿、時間 ∝ 運算量 → 運算
- 資料大、存取跳躍、資料加大效能驟降 → 記憶體 / 快取 / 匯流排
- CPU 閒但整體慢 → I/O / 周邊 / 通訊等待
- 加執行緒沒變快或更慢 → 鎖競爭 / false sharing
- 輸入稍大時間暴增 → 演算法複雜度
- 在等另一元件（topic、FIFO、DMA 完成）→ 管線不平衡、序列化執行

手法（通常收益大 → 小）：
1. 演算法：降複雜度、換資料結構、快取 / 查表、提早結束
2. 卸載與平行：DMA 搬資料；PIO 處理時序 I/O 與位元打包；第二核心分工或管線；雙緩衝（ping-pong）讓計算與搬運重疊
3. 同步：臨界區縮到最短（計算移出鎖外）；各自累計最後合併；原子操作取代鎖；避免 false sharing
4. 記憶體：循序存取；熱碼放 SRAM；對齊、32 位元寬讀寫；熱路徑不 malloc
5. I/O：批次處理；移除熱路徑 printf；ROS 2 callback 不阻塞
6. 微優化：2 的冪次用位移 / 遮罩；branchless；迴圈展開；`__builtin_popcount/clz/ctz`
7. 編譯器：-O2 / -O3 / -Os；inline、restrict、const；看 objdump / `.dis`（先確認評分是否允許改旗標）

鐵則：正確性第一；先量測；只優化瓶頸；一次改一處；有效就 commit。
Amdahl：p = 0.6、s = 3 → 1.67 倍；s = ∞ → 上限 2.5 倍。

## L22-06

【參考卡｜優化 6/6｜量測方法與 RP2350 速查】
以下是正確的參考資料，若與你的記憶不同，以這張為準。平台：RP2350（Pico 2），非 RP2040。
量測：
- Linux：`clock_gettime(CLOCK_MONOTONIC, &t)` 包住區段，結果印到 stderr（不污染評分 stdout）；`time ./prog`；多跑幾次取中位數。
- 容器內 perf 很可能不能用（Docker 預設 seccomp 擋 `perf_event_open`），改用程式內計時或 gprof（`-pg`）。
- RP2350：`uint64_t t0 = time_us_64();` 前後相減；短區段重複 N 次再除 N；printf 放量測區段外（USB stdio 很慢）。
- ROS 2：`ros2 topic hz / bw / delay /topic`（delay 需訊息有 header 時間戳）。
量測陷阱：
- 量到 debug 版：用評分相同旗標；pico-sdk 的 Release 預設 `-O3`，Debug 為 `-Og`，以評分腳本為準。
- 結果沒被使用會被編譯器刪掉：用 `volatile` 接或印出結果。
- 冷啟動較慢；變異大時看中位數與最小值。
RP2350 情況 → 首選手法：
- CPU 迴圈搬大量資料 → DMA
- bit-bang GPIO / 精確時序 → PIO
- 一核忙一核閒 → 雙核分工或管線
- CPU 等 DMA 完成 → 雙緩衝重疊
- 熱迴圈在 XIP flash 執行 → 放 SRAM（`__not_in_flash_func`）
- RISC-V（Hazard3）核心用 float / double → 改定點數（Hazard3 無 FPU，浮點全靠軟體模擬）
- 大量位元操作 → Zbb / Zbs 指令、builtin
- 周邊輪詢浪費 CPU → 中斷或 DMA + DREQ

## L23-06

【參考卡｜速學 6/6｜五步速學法與類別重點】
以下是正確的參考資料，若與你的記憶不同，以這張為準。
目標：只學到能解這題的程度；先跑起來再讀；找類比；題目附的文件與程式碼最可靠（網路資料可能版本不同）。
五步（共約 60 分）：
1. 定位（5 分）：類別、解決什麼、輸入輸出、在本題跟誰互動、像什麼、版本
2. 跑起來（15–20 分）：範例來源依序為題目附的範例 → 專案內已用到的地方（`grep -rn 關鍵字 .`）→ 官方 Getting Started → 官方 repo 的 examples/tests → header 註解。原封不動先跑一次。
3. 建模型（15 分）：3–7 個核心概念、生命週期、5–10 個關鍵 API、限制、陷阱。通用框架：初始化 → 設定 → 啟動 → 等待 / 處理 → 釋放（例：DMA 為 claim channel → configure → start → wait → release；ROS 2 node 為 init → create pub/sub → spin → shutdown）。
4. 小改動（10 分）：改一個參數，先寫預測再跑；預測錯處就是誤解。
5. 對準題目（10 分）：用到哪些概念 / API、哪些效能選項。
依類別先看：
- 硬體周邊：datasheet Overview、方塊圖、Programmer's model、SDK 範例；問設定順序、FIFO / DMA / IRQ、時脈、資源數
- 函式庫：header、範例；問初始化順序、阻塞、記憶體誰管、回傳值
- 框架：架構概念、CLI；問誰呼叫誰、callback 在哪個執行緒
- 協定：封包格式、狀態機；問分框、校驗、流控、endianness
讀 header：`grep -n "^[a-z].*(" x.h`（函式）、`grep -n "typedef\|struct\|enum" x.h`（型別）。datasheet 搜 "must" "note" "errata" "not supported"。
止損：跑不起來超過 20 分 → 環境問題問監考，或從專案現有程式碼下手；整體超過 60 分 → 先做別題；只佔題目一小部分 → 照範例當黑盒子用。
