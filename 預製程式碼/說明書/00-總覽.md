## 0.3 環境：考場有什麼、你的電腦要裝什麼

### 考場（依官方範例包 Dockerfile 與考前練習推測）

| 東西 | 推測 | 怎麼確認 |
|---|---|---|
| 作業系統 / 容器 | Ubuntu + Docker，ROS 2 Jazzy（官方練習用 `ros:jazzy-ros-core`） | `cat /etc/os-release`、`echo $ROS_DISTRO` |
| pico-sdk | 有（正式考試的容器才有；練習包註明「no pico-sdk」） | `echo $PICO_SDK_PATH`；版本看 build 後的 `build/generated/pico_base/pico/version.h` |
| 交叉編譯器 | 有 `arm-none-eabi-gcc`；RISC-V 不一定 | `arm-none-eabi-gcc --version`、`ls /usr/bin/*riscv*` |
| 板子 | Raspberry Pi Pico 2（RP2350），可能好幾片 | `ls /dev/ttyACM*`（要 `--privileged` 的容器才看得到） |
| 評分 | GitLab CI（Online Judge），commit 後自動跑 | 讀出題 repo 的 `.gitlab-ci.yml` |
| LLM | 只能用考場提供的小模型；不能上傳檔案、貼上長度有限 | 開考時確認 |

**pico-sdk 版本會影響幾件事**（第 3 章 3.6、第 6 章 6.6 有細節）：

| 版本 | `dma_encode_transfer_count()` | RISC-V `-march` | RISC-V `-mstrict-align` |
|---|---|---|---|
| 2.0 / 2.1 | 沒有（`pico/app_dma*.c` 已經自己補上；你自己寫的程式要直接填筆數） | 預設 `rv32imac_zicsr_zifencei_zba_zbb_zbs_zbkb` | 不加 |
| 2.2.0 | 有 | 同上；`-DPICO_COMPILER=pico_riscv_gcc_zcb_zcmp` 才用 Zcb/Zcmp | 不加 |
| 2.3.0 | 有 | 自動依序試 `-mcpu=hazard3-rp2350` → zcb_zcmp → rv32imac | 不加 |
| 2.3.1 | 有 | 同 2.3.0 | 預設加（`-DPICO_NO_STRICT_ALIGN=1` 可關） |

## 0.5 共同慣例

### `TODO(改這裡)`

- 所有要依題目改的地方都標了 `TODO(改這裡)`，後面接一句說明。用這個指令一次列出某個資料夾的全部位置：

```bash
grep -rn "TODO(改這裡)" 預製程式碼/pico
```

- 第 9 章附錄 9.1 有全部 78 處的總表（檔名、行號、那一行的程式、說明）。
- 改的時候：**名稱、協定欄位、常數的意思**照原樣，只改值。改完一處就 build 一次。

### 檔頭註解

每個程式檔的開頭都有繁中註解：這個檔案做什麼、怎麼 build / 執行、設計重點。打開檔案先讀檔頭，再搜尋 `TODO(改這裡)`。

### 測試程式的輸出

| 資料夾 | 測試檔 | 成功的樣子 |
|---|---|---|
| `algo/` | `*_test.c` | 最後一行 `結果：全部通過` |
| `bits-riscv/` | 各 `.c` 內建測試、`asm_test.c` | `<名稱>: ALL PASS` |
| `linux-perf/` | `parallel_template.c`、`pipeline_template.c` | `結果：全部正確` |
| `ros2/` | `frame.py` 不加參數 | `frame.py 自我測試 OK` |
| `pico/` | 開機自我測試（印在序列埠） | 各項印 `PASS`（沒有在板子上實測過，見第 3 章） |

### 「實際執行輸出」怎麼讀

- 各章貼的輸出都是撰寫時（2026-11-12）在一台 x86_64、4 核的 Linux 容器上真的跑出來的：host gcc 13.3、Python 3.13、arm-none-eabi-gcc 13.2、pico-sdk 2.2.0（部分也用 2.1.1）、riscv64-unknown-elf-gcc + qemu-riscv32。**沒有實體 Pico、沒有 ROS 2**，所以板子上的輸出和 `rclpy` 程式都標 ⚠️。
- 輸出裡的 `$S/…`（例如 `$S/ch01/work/pico`）是撰寫時放複本、做實驗的暫存資料夾，**不在 repo 裡**。自己照做時換成你的工作資料夾（例如 `~/work`）。
- 速度、倍數會依電腦不同；看的是「相對快多少」和「結果對不對」，不是絕對數字。

### 驗證標記

- ✅：在這台電腦上實際編譯 / 執行過，輸出貼在對應章節。
- ⚠️：沒有實測（多半是因為需要實體板子或 ROS 2），只對照過原始碼或官方文件。考場上要先自己確認。

## 0.6 把預製程式碼帶進考場

1. 考前放到考場打得開的地方：**私人** GitHub repo（這個 repo）或 Google Drive。不要公開。GitHub 頁面上的 Copilot 按鈕不要按（考場規則只准用考場的 LLM）。
2. 考場上取用檔案的方法（照方便程度）：
   - 在瀏覽器打開 GitHub 上的檔案 → 按 `Raw` → 全選複製 → 在 VS Code 新增檔案貼上。
   - 整包：GitHub 頁面 `Code` → `Download ZIP`，解壓縮後複製需要的檔案到出題 repo（**不要**把整個 `預製程式碼/` 加進出題 repo 的 commit）。
3. 只複製這一題需要的檔案。複製進出題 repo 後，用 `git status` 確認沒有多餘的檔案被 commit。
4. 紙本：印出本說明書 PDF、`prompt工具包/print/` 的 PDF。

## 0.7 搭配考場的小模型

- 考場模型能貼的長度有限，**一次只貼一個檔案的一小段**（一個函式，或 `TODO(改這裡)` 前後 20～40 行）。
- 先貼 `prompt工具包/cards/09-template-adapt.md` 的「範本 1/7」告訴模型你有範本，再用「範本 2/7」對照題目規格和範本、「範本 3/7」改一段 `TODO`、「範本 7/7」檢查改完的結果。
- 模型說的 API、暫存器、常數一律自己查證：pico-sdk 的 header、本說明書的速查表（每章 N.7）。
- 數字（byte 數、位元位置、CRC）交給程式算：`python3 ros2/frame.py diff …`、`bits-riscv/rv32_encode_decode.c`、`algo/*_test.c`，不要讓模型心算。
