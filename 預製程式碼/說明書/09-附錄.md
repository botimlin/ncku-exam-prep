## 9.2 名詞解釋

| 名詞 | 一句話解釋 | 在哪一章 |
|---|---|---|
| ROS 2 | 機器人軟體框架；程式切成很多 node，node 之間用 topic 傳訊息 | 2 |
| node | 一個參與 ROS 2 通訊的程式單位（一支 Python 程式通常建立一個） | 2 |
| topic | node 之間傳資料的通道，有名稱（如 `/number`）和固定的訊息型別 | 2 |
| publisher / subscriber | 往 topic 發資料的一方 / 從 topic 收資料的一方 | 2 |
| QoS | 傳輸品質設定；`reliable`（保證送到、會重送）和 `best_effort`（丟了就算）不相容時收不到資料 | 2 |
| namespace | topic 名稱的前綴，例如 `pico0` 讓相對名稱 `input` 變成 `/pico0/input` | 2、4 |
| `rclpy` / `rclc` | ROS 2 的 Python 函式庫 / micro-ROS 在 MCU 上用的 C 函式庫 | 2、4 |

| agent（micro-ros-agent） | 電腦上的程式，把序列埠上 micro-ROS 的 XRCE-DDS 訊息轉成一般 ROS 2 topic | 4 |
| MTU | 一次傳輸單位的最大位元組數；micro-ROS 預設 512 | 4 |
| Pico 2 / RP2350 | 樹莓派的微控制器板 / 它上面的晶片；雙核心，可選 ARM Cortex-M33 或 Hazard3 RISC-V | 3 |
| pico-sdk | 樹莓派官方的 Pico C 開發套件（CMake + 函式庫） | 3 |
| `.uf2` | 燒錄檔；按住 BOOTSEL 插 USB，把它拖進出現的磁碟就燒進去了 | 3 |
| BOOTSEL | Pico 上的按鈕；按著插 USB 會進入燒錄模式 | 3、8 |
| USB CDC / `/dev/ttyACM0` | Pico 用 USB 模擬的序列埠；Linux 上的裝置名稱 | 2、3 |
| 序列埠 / UART | 一次傳一個 byte 的通訊介面 | 2、3 |
| frame / 封包 | 一段有固定格式（標頭、長度、資料、校驗碼）的 bytes | 2、3 |
| CRLF | `\r\n`；pico-sdk 的 stdio 預設把 `\n` 改成 `\r\n`，會弄壞二進位資料 | 2、3 |
| endian（大小端） | 多 byte 數字在記憶體裡的排列順序；小端（little-endian）低位 byte 在前 | 2、6 |

## 9.3 RP2350 / pico-sdk 常數速查

數值對照 pico-sdk 2.2.0 的 `src/rp2350/hardware_regs/include/hardware/platform_defs.h` 和 `hardware/regs/*.h`。

| 項目 | RP2350 | RP2040（不要搞混） |
|---|---|---|
| 核心 | 2 × Cortex-M33 或 2 × Hazard3 RISC-V（開機選） | 2 × Cortex-M0+ |
| SRAM | 520 KB | 264 KB |
| DMA channel（`NUM_DMA_CHANNELS`） | 16 | 12 |
| DMA IRQ（`NUM_DMA_IRQS`） | 4 | 2 |
| DMA transfer count | 低 28 bits 是筆數，[31:28] 是 MODE | 32 bits 都是筆數 |
| PIO block（`NUM_PIOS`） | 3（每個 4 個狀態機，共 12） | 2（共 8） |
| PIO 指令記憶體 | 每個 block 32 條 | 每個 block 32 條 |
| 硬體 spinlock（`NUM_SPIN_LOCKS`） | 32（SDK 預設用軟體 spinlock，因為 RP2350 勘誤 E2） | 32 |
| SIO FIFO 深度（每個方向） | 4 | 8 |
| 中斷數（`NUM_IRQS`） | 52 | 32 |
| USB 序列埠 | `/dev/ttyACM*`（`pico_enable_stdio_usb`） | 同左 |
| `PICO_BOARD` | `pico2` | `pico` |
| `PICO_PLATFORM` | `rp2350-arm-s`（預設）或 `rp2350-riscv` | `rp2040` |
