# 提交檢查與時間策略（精簡版，給自己看）

## 提交規則
一次只能一份在評分中；push 觸發 pipeline 的話，等跑完再 push。不得干擾評分系統。

## 提交前
- [ ] 範例輸入 diff 完全一致；邊界（空 / 最小 / 最大 / 非 4 倍數）測過
- [ ] 多執行緒跑 20 次結果一致
- [ ] `git diff --stat <起點>`：沒改到禁改檔案
- [ ] 介面、輸出格式不變；`grep -rn "printf\|DBG\|print(" src/` 清掉 debug
- [ ] 乾淨重建成功（刪 build/）；新檔、新函式庫已加入 CMake
- [ ] 建置設定與評分一致（Release、ARM/RISC-V）
- [ ] commit 訊息清楚；push 到指定 branch；`git tag best-vN` 標最佳版
- [ ] 送出後記錄：`# | 時間 | commit | 內容 | 分數`

## 時程（以 16:30 截止規劃）
官方：09:10–12:00、13:00–16:30 作答（12:30 教室重開可續作答）；16:30–17:30 預計截止，可能延長至 19:30。
| 時間 | 目標 |
|---|---|
| 09:00–09:10 | 聽說明，記規則、評分、提交方式 |
| 09:10–09:20 | 開對話、貼開場、盤點檔案 |
| 09:20–10:00 | 所有題目先看一遍，填理解卡，估 分數 / 時間 |
| 10:00–10:30 | baseline、確認能編能交 |
| 10:30–12:00 | 先拿最確定的分 |
| 12:00–12:30 | 吃飯休息 |
| 12:30–13:00 | 更新狀態卡，排下午優先序 |
| 13:00–15:30 | 主要優化 |
| 15:30 | 檢查點：砍掉做不完的 |
| 16:00–16:30 | 只收尾，確認最佳版已提交 |

## 決策
卡 20 分換方法｜卡 40 分回退改做別的｜方案要 2 小時以上就先做別的｜15:30 後不開大改動｜16:00 後只收尾｜模型變差就 /摘要 開新對話｜設備問題舉手問監考

## 考場規則（官方 FAQ）
只能用考場的小模型（網頁介面、不能上傳、貼上有長度限制）｜禁止其他 LLM、Copilot、搜尋引擎 AI 摘要、Gmail / LINE / Discord｜可帶紙本筆記｜可登入個人帳號、開雲端筆記
