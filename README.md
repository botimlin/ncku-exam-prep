# 成大資工特殊選才上機考：引導式 prompt 工具包

給考場提供的大語言模型當參考文件用，也是自己的解題流程框架。
所有檔案都是純 Markdown，打開來就能讀，也能直接貼給模型。

## 考場條件（官方 2026-11-10 常見問題信）

- 考場模型：部署在消費級硬體上的小模型，網頁聊天介面，**不能上傳檔案**，對話與單次貼上長度有限制。
- 小模型對 RP2350 / pico-sdk / ROS 2 Jazzy 的細節多半不清楚，可能和 RP2040 混淆。**它的用途是根據你貼的資料推理，不是提供硬體知識。**
- 可上網、可登入個人帳號、開自己的雲端筆記；可帶紙本筆記與書。
- 禁止：其他 LLM、AI agent、Copilot、**搜尋引擎 AI 摘要**、Gmail / LINE / Discord 等通訊服務、個人裝置。

## 大小預算

- `cards/` 每張 ≤ 1200 字元；開場卡 1 約 400 字元。
- `lite/` 每份 ≤ 4000 字元。
- `full/` 不設上限，考前閱讀用，考場一般貼不下。

## 使用方式

1. 考前：填好開場卡（`cards/00-starter.md` 卡 1）的 `{{…}}`；`lite/00-starter.md`、`full/01-context.md` 也一起填。列印 `print/` 的 PDF，把 `08-docs-map.md` 的連結存成書籤並逐一測試。
2. 開考：開新對話 → 貼開場卡 1（要用範本再貼 `09-template-adapt.md` 範本 1/7）→ 照 `10-exam-day-flow.md` 開考 1→5 走完前 30 分鐘。
3. 每個問題：貼**一張**相關卡片，或從官方文件剪一小段（標明出處與章節），資料放在 `<<<資料 開始>>>`／`<<<資料 結束>>>` 之間。
4. 卡片是一條鏈：「定位」卡（分類、找位置，不修）→「修改」卡（最小 patch + 1 行驗證指令）→ 跑驗證。標題後的 `→` 告訴你下一張。
   - 建置錯誤：`05` 建置 2／3 → 建置 4。執行錯誤：`06` 工具 1／2／3／5 或 `04` 除錯 1 → `06` 工具 7。改範本：`09` 範本 2／4／5／6 → 範本 3 → 範本 7。
5. 對話太長、模型變差：直接開新對話重貼開場卡 1，再貼你要用的那張卡（每張都能單獨用）；需要延續時才用狀態卡（開場卡 3）。
6. 模型說的 API 一律自己查證：官方 header（`08-docs-map.md` 有網址）或紙本。
7. 工具的完整手冊（給自己讀、不貼給模型）：`../預製程式碼/tools/`（`cmake.md`、`debug-host.md`、`debug-pico.md`、`debug-ros2.md`、`vscode.md`）。

## 為什麼卡片這樣寫（小模型提示詞原則）

考場是消費級硬體上的小模型：記性短、容易忘規則、容易編造。卡片照下面 10 條寫，臨場自己寫新提示詞也照這樣：
1. **一張卡只做一件事**：定位、修改、驗證分開，用 `→` 串起來。
2. **固定輸出格式 + 長度上限**：「只輸出下面格式，每項 ≤ 2 行」；盡量讓它做選擇題（A–H 分類、填表、OK / 有問題）。
3. **資料放在分隔線裡**：`<<<資料 開始>>>`…`<<<資料 結束>>>`；只准根據資料，沒有就寫「資料中沒有」。
4. **要證據**：每個結論附「證據：『原文』」，你才能 10 秒內查核。
5. **指令頭尾各一次**：任務句放最前面，輸出格式放在資料後面（小模型讀完長資料會忘了前面的指令）。
6. **給一個小範例**（2–4 行），格式不明顯時特別重要。
7. **改程式只要最小 patch**：「檔名:行號 / 修改前 / 修改後」，限制行數，名稱、協定欄位、`TODO(改這裡)` 照原樣。
8. **規則少而具體**：每張 ≤ 5 條，用「要做什麼」的正面句。
9. **英文任務句**：每張提示卡第一行是 `Task (EN): … Answer in Traditional Chinese.`，模型中文弱時靠它定錨；中文是同一件事的詳細版。
10. **每張自給自足 + 內建驗證**：新對話直接貼就能用；修改卡一定附「1 行驗證指令 + 成功的樣子」。

### 壓力測試學到的（RTX 4090 上 10 個 3B～20B 模型實測，`stress-test/`）
11. **小模型不會數 byte、不會對齊欄位** → 交給程式做（`python3 ros2/frame.py diff 預期 實際`），模型只看結果選原因。
12. **表格的列先填好**，模型只填格子；要比對兩邊時用「項目 | A 的值 | B 的值 | OK/NG」：先抄值、再判斷。
13. **先寫證據和原因，最後才選答案**；選項要「照抄字母 + 文字」（例：`類別：D 找不到 header`），字母才不會選歪。
14. **選項後面附錯誤關鍵字和修法**（例：`A 找不到 SDK（SDK location、PICO_SDK_PATH）`、`A 多了 0D → Pico 端 PICO_STDIO_DEFAULT_CRLF=0`）：小模型靠比對關鍵字選對，修法直接照抄。
15. **範例會被照抄**（檔名、行號都會）→ 範例用和題目不同的名字，並標「只示範格式，內容不要照抄」。
16. **機械式規則比抽象規則有效**：「修改後 = 原本那行，只在 `)` 前加新名稱」勝過「照原本寫法」。
17. **3B 等級的模型格式跟得上、判斷常錯** → 模型給的證據一定自己對一次原文。
18. **規則常被忽略，欄位一定會被填** → 重要的規則改寫成輸出欄位（例：「看不到定義的函式：」「要加的函式庫：」「合併用：」）。
19. **欄位名要短**；擇一的寫法放在上面一行「填法：…只寫「可以」或「不行」」。把「可以 / 不行」寫在欄位裡，模型會兩個都抄；說明塞進欄位名，模型會把欄位名整個省掉。
20. **檢查清單直接做成表格的列**（「| 3 write_increment … | | |」），模型才不會把問題填錯列；要判斷 diff 時先叫它逐行抄 `+` / `-` 的行。
21. **小模型沒有硬體知識**（例如 DMA 預設不遞增寫入位址）→ 同一個對話先貼對應的參考卡，模型回「收到」再貼提示卡。
22. **推理模型（gpt-oss、qwen3）會先想很久**：回覆很慢或很長是正常的；如果考場介面有字數上限而回答被截斷，就把資料切小一點再問。實測（4k context）：gpt-oss 在訊息最後加一行 `Reasoning: low`，想的量少約 1/4、快約 20%、分數不變（可以加）；qwen3 加 `/no_think` 沒有效果。被截斷的次數兩種都不變 → 真正有用的是切小資料、常開新對話。
23. **對話不要拉太長**：4k context 的模型，同一個對話貼 5～6 張卡就會超出（實測被截斷，表格只寫 1～2 列）。每做完一小步就用開場卡 3/3 的狀態卡開新對話；每張卡本來就能在新對話直接用，單獨貼的分數也比較高。

## 放到網路上的注意事項

- 放在考場打得開的地方：**私人** GitHub repo 或自己的雲端硬碟（官方允許登入個人帳號）。不要公開，以免被其他考生拿去用。GitHub 頁面上的 Copilot 按鈕不要碰。
- 網址要短、好記；考前定版，考試期間不要修改。
- 準備網路連不上的備案：核心流程自己要記得。

## 準確性

`domain/`、`cards/`、`08-docs-map.md` 的內容都盡量對照官方文件（pico-sdk 原始碼、RP2350 datasheet、ROS 2 官方文件、RISC-V 規格）確認過；無法確認的地方標了 `⚠️未驗證`。考試時仍以題目提供的文件和實際 header 為準。
